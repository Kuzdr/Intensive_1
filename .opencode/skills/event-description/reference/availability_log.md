## 13.10.2026, ~20:00 (мск) — elementy.ru не отвечает (кнопка «Обновить данные» зависла)

- `https://elementy.ru/events`:
  - 1-я попытка (urllib, UA по умолчанию) — `TimeoutError` через 20 с;
  - 2-я попытка (requests, UA браузера — как в `scrape.py`) — `ReadTimeout`
    `HTTPSConnectionPool(host='elementy.ru', port=443): Read timed out
    (read timeout=30)` через 30 с;
  - повтор через ~10 мин (3-я попытка, requests, timeout 40) — снова
    `ReadTimeout` через 40 с.
- Как проявилось: при нажатии «Обновить данные» сервер замер на шаге
  `scrape`, ~17 %, «Загрузка списка событий с elementy.ru…» — процесс
  `scrape.py` не завершался, кнопка была заблокирована (`running=true`),
  способа возобновить не было.
- Причина описанного «зависания навсегда»: `timeout` в requests ограничивает
  время МЕЖДУ порциями данных, а не общее; при «замершем» соединении он не
  срабатывает. Это НЕ связано с правками интерфейса (менялся только
  `build.py` — шаблоны/JS/CSS; `scrape.py`/`serve.py` оставались прежними,
  их последнее изменение — коммит 7d95bcc).
- Мера (правило 13.10.2026): в `serve.py` добавлен ЖЁСТКИЙ предел времени на
  шаги обновления — `SCRAPE_LIMIT` (300 с) и `BUILD_LIMIT` (240 с): при
  зависании шаг останавливается сам, обновление завершается понятной ошибкой,
  кнопка разблокируется. Тот же предел добавлен в перезагрузку одного события
  и в пересборку сайта после действий с прототипами.
- Итог на 13.10.2026 ~20:10: elementy.ru всё ещё не отвечает (повтор также
  неудачен). Обновление данных отложено до восстановления сайта-источника.
