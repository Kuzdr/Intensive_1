# Пост в Телеграм

Пост собирается из данных `data/events.json` (поля событий: `date_iso`, `time_start`,
`time_end`, `city`, `place`, `price_short`, `lecturer`, `title`, `lectory`, `url`).

## 1. Диапазон дат по умолчанию

Каждый день пользователь публикует один пост с анонсами на несколько дней вперёд.
При запросе «пост по умолчанию» диапазон считается так (время — московское):

- «от» = сегодня, если сейчас раньше 18:00, иначе завтра;
- «до» зависит от дня «от»:
  - пт или сб → вс;
  - ср или чт → пт;
  - пн или вт → ср;
  - вс → вт.
- Исключение: если «от» выпал на вечер воскресенья, то «от» = понедельник, значит «до» = среда
  (см. правило выше: пн → ср).
- В посте перечисляются только дни из диапазона, в которых есть события
  (день без событий пропускается, ещё не наступивший и не имеющий событий в данных — тоже).

Пользователь может задать свой диапазон (конкретные даты или «на неделю вперёд»).

## 2. Вводный абзац

Первая строка поста:

```
Научно-популярные лекции|https://elementy.ru/events?from=tg в понедельник|URL_дня, вторник|URL_дня и среду|URL_дня:
```

- Ссылка-«якорь»: `Научно-популярные лекции` → `https://elementy.ru/events?from=tg`.
- Дни недели (nominative, в нужном падеже после «в»): понедельник, вторник, среда, четверг,
  пятница, суббота, воскресенье.
- URL дня: `https://elementy.ru/events?archive=2&evdate=<timestamp>&period=d&from=tg`,
  где `<timestamp>` — Unix-время **00:00 московского времени** нужной даты.
- Дни разделяются запятой, перед последним — «и». После двоеточия — перевод строки.
- После вводного абзаца и перед каждым следующим событием — пустая строка (двойной абзац).

## 3. Структура поста на каждое событие

Каждое событие — строго ТРИ абзаца, ничего больше (никаких описаний лекций):

```
Дата, время, город, площадка (цена)

**Автор(ы)**

Название|ссылка (подзаголовок)
```

Если автор не указан, второй абзац отсутствует, а в третьем абзаце НАЗВАНИЕ
выделяется жирным: `**Название**|ссылка (подзаголовок)`. Подзаголовок жирным
НЕ выделяется никогда.

Между соседними событиями — пустая строка (двойной абзац).

### Абзац 1 — дата и место

```
ДД.ММ, ЧЧ:ММ, Город, Площадка (цена)
```

- Дата — `ДД.ММ`, время — `ЧЧ:ММ` — только начало события (`time_start`),
  время окончания (`time_end`) НЕ выводится. Если события занимают весь день
  или время не указано — время можно опустить.
- Город и площадка через запятую. Из названий организаций УБИРАЕМ инициалы:
  `Библиотека им. Н. А. Некрасова` → `Библиотека им. Некрасова`. Сокращения
  типа «им.», «МГУ», «МПГУ», «РАН», «ВДНХ» не трогаем.
- Если цена есть:
  - числовая (например `1800 ₽` в данных) → `(1800 руб.)`;
  - «Бесплатно» → `(бесплатно)`;
  - диапазон `от X до Y руб.` → только нижняя граница: `(от X руб.)`,
    дополнительные записи (льготы, «онлайн») сохраняются;
  - пробелы между группами цифр убираются: `10 000` → `10000`.

### Абзац 2 — авторы

```
**Автор1, Автор2**
```

- Авторы — из поля `lecturer` события (краткое описание в списке), через запятую,
  жирным. НЕ из аннотации.
- Если авторов нет — абзац не выводится.

### Абзац 3 — название и ссылка

```
Название|ссылка (подзаголовок)
```

- Название — заголовок события, оформляется ссылкой `Название|URL`,
  где URL = `url` события из данных + `?period=m&from=tg`.
- Если автора нет — название выделяется жирным: `**Название**|ссылка`.
- Подзаголовок в скобках после ссылки — ФАКУЛЬТАТИВНО. Это поле события `lectory`,
  но на практике там может оказаться НЕ лекторий, а что-то другое (например название
  лекции или цикла). Выводится в скобках в любом случае, если оно нетривиально
  по сравнению с площадкой (городом/местом), а не «выводится» из неё автоматически:
  - показать: (Medio Modo), (Лекторий «Архэ») — они проводят события на разных площадках;
  - НЕ показывать: (Лекторий.ВДНХ), (Лекторий «ВСмысле»), а также те, что совпадают
    с площадкой (Открытый лекторий Московского зоопарка, Лекторий Библиотеки Планетария 1).

## 4. Правила удаления инициалов

Из названий площадок (организаций) убираем инициалы отдельных людей.

- Пример: `Библиотека им. Н. А. Некрасова` → `Библиотека им. Некрасова`,
  `Астрокомплекс МПГУ им. К. Э. Циолковского` → `Астрокомплекс МПГУ им. Циолковского`.
- Убираются буквы-инициалы (одна заглавная буква с точкой), стоящие перед фамилией.
  Сокращения типа «им.», «МГУ», «МПГУ», «РАН», «ВДНХ» не трогаем.

## 5. Что не попадает в пост

- Только предстоящие события (дни до «от» не включаются).
- Событие с датой раньше сегодняшнего дня — пропустить.
- В пост не включаются события, помеченные как спорные, требующие подтверждения
  (если такие есть в данных).

## 6. Формат вывода

Пост выводится в чат как готовый текст для публикации, оформленный кодом
(блок с кнопкой «копировать»), чтобы при вставке в Телеграм не протаскивалось
лишнее форматирование. Внутри блока — ровно то, что пойдёт в Телеграм:
вводный абзац, затем пустая строка, затем события. Между событиями — пустая строка.
Перед выводом поста пользователю НЕ вносим изменения на сайт — показываем пост здесь,
даём пользователю отредактировать правила в `SKILL.md`, только после одобрения
реализуем кнопку «Пост в Телеграм» на сайте.
