# Обновление данных (общий и по организаторам)

## Общий цикл (основной источник — elementy.ru)

1. **Сбор с «Элементов» (основной путь):** `python -X utf8 scrape.py` — обновляет `data/events.json` (merge: новые/изменённые/удалённые, пометка `updated`, порядок `ord` и т.д.). Локально/через `serve.py` кнопка «Обновить данные» выполняет тот же цикл + `build.py` + коммит/пуш (по правилам проекта).
2. **Сборка сайта:** `python -X utf8 build.py` — генерирует `site/` из `data/events.json` и прототипов.
3. **Проверки перед коммитом (обязательно):** `python -X utf8 tools\check_skills.py` (и при правках прототипов — соответствующие проверки по правилам AGENTS.md). Коммит/пуш допустимы без отдельного запроса, если всё корректно (см. AGENTS.md).
4. **Защита от сбоев:** при пустой/подозрительной афише «Элементов», нуле прочитанных страниц и т.п. `scrape.py` **не должен** затирать `data/events.json` — следовать поведению и логам из AGENTS.md (`availability_log.md` при проблемах доступа).

Подробности и запреты (пустая афиша = сбой и т.д.) — в `AGENTS.md` и `ПАМЯТКА.md`.

## Список источников мониторинга

- **Файл:** `data/sources_list.md` — страницы-списки/афиши по организаторам (не отдельные карточки событий, если не оговорено). Обновляется вручную.
- При добавлении нового организатора/страницы: внести в `data/sources_list.md`, для Timepad-URL всегда указывать основной способ **запуск Edge через CDP** (см. ниже).

## Правила обхода источников (кратко)

- **Timepad (`*.timepad.ru`, страницы списков/афиш и карточки при необходимости): ОСНОВНОЙ способ — Edge через CDP.** Скрипты/инструменты проекта: `tools/cdp_read.py`, `tools/timepad_parse.py`; кэши в `data/raw/cdp/` (при наличии сохранённых страниц). Не тратить время на повторный `webfetch` как первый шаг для Timepad; при необходимости открыть страницу в Edge вручную и сохранить HTML для разбора скриптами.
- **`elementy.ru`:** основной сбор через `scrape.py`/`tools/elementy_detail.py`; при недоступности — правила из AGENTS.md и запись в `availability_log.md`.
- **VDNH (`vdnh.ru`) и JS-тяжёлые сайты:** `webfetch` может вернуть только навигацию; запасные — кэши в `data/raw/`, CDP/ручной просмотр в Edge.
- **Обычные сайты организаторов:** сначала `webfetch` (text/markdown), при ошибках — повторы по правилу недоступности, затем кэши/CDP/ручной просмотр; фиксировать проблемы в `availability_log.md` при необходимости.

## Архэ (особенности)

- Проверять **все страницы-списки** из `data/sources_list.md` (раздел Архэ), включая обе ленты Timepad (`arhe-events.timepad.ru/events/`, `tsentr-arhe-v-sankt-peter.timepad.ru/events/`) — доступ к Timepad через **Edge/CDP**.
- **Дубли URL событий:** одни и те же события могут встречаться в разных форматах; нужно «склеивать» дубли по смыслу (дата/название/автор). Предпочтения адресов события: (1) `https://arhe.msk.ru/?p=<ID>`, (2) `https://arhe.msk.ru/?post_type=tribe_events&p=<ID>` (ID между форматами может отличаться на 1 — сверять по содержимому), (3) текстовый `https://arhe.msk.ru/?tribe_events=…` — только если других нет.
- При сборе прототипов/данных из Архэ учитывать эти правила, чтобы не плодить дубли.

## Проверка обновлений по другим организаторам (рекомендация)

1. Открыть `data/sources_list.md`, пройти по нужным блокам организаторов.
2. Для Timepad-списков — использовать Edge/CDP (см. выше), не полагаться на `webfetch`.
3. Зафиксировать найденные новые/изменившиеся события в прототипах/заметках по обычным правилам проекта (`event-description`, проверки авторов/дублей на «Элементах» и т.д.).
4. После изменений в `data/` и/или прототипах — `build.py`, проверки, коммит/пуш по правилам AGENTS.md.

## Что делать, если источник недоступен

- Следовать правилу из AGENTS.md: сообщить пользователю, записать в `.opencode/skills/event-description/reference/availability_log.md` (дата/время, URL, ошибка, попытки), повторы 1 мин → 5 мин, дальше по решению пользователя. После восстановления — перепроверить и дописать результат в `notes` прототипа при необходимости.
