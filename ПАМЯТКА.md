## 1. Как открыть терминал (PowerShell)

Самый простой способ:
1. Нажми **Win + R** (Win — клавиша с логотипом Windows).
2. Впиши `powershell` и нажми **Enter**.

Откроется окно с тёмным или синим фоном и строкой вида `PS C:\Users\mv>` — это и есть терминал.

> Совет: если нужно открыть терминал сразу в папке проекта — открой `C:\_PROJ\Zerocoder\Intensiv_1` в проводнике, кликни в адресную строку, сотри путь, напиши `powershell` и нажми Enter.

## 3. Как собрать сайт локально

В проекте три скрипта: **сбор данных**, **сборка сайта** и **локальный сервер**.

```
python scrape.py     # скачать события с elementy.ru → data/events.json
python build.py      # собрать сайт из данных → папка site/
python serve.py      # локальный сервер: http://localhost:8000
```

После сборки сайт можно открыть так:
```
Start-Process site\index.html
```
(или просто открой файл `C:\_PROJ\Zerocoder\Intensiv_1\site\index.html` двойным кликом).

## 4. Кнопка «Обновить данные» на главной странице

Работает только на **локальном сервере** (`python serve.py`, адрес http://localhost:8000). На публичной странице (GitHub Pages) кнопка вместо обновления покажет подсказку и дату/время последнего обновления данных.

Клик по кнопке открывает маленькое окно с вопросом **Да / Нет** — обновление запускается только после ответа «Да» (всё автоматически):
1. удаляются прошедшие события;
2. добавляются новые, которых ещё не было на сайте;
3. для уже имеющихся сравниваются основные поля (название, авторы, дата, лекторий, место, цена): если ничего не изменилось — описание сохраняется как было; если изменилось — описание перепорождается и событие помечается «обновлено»;
4. сайт пересобирается и изменения отправляются на GitHub (`git add -A`, `git commit`, `git push`) — публичная версия обновится сама.

После ответа «Да» окно закрывается само, а под кнопкой появляется служебная панель: линейка хода обновления с процентами. Когда всё готово, страница через пару секунд обновляется целиком (чтобы показать свежие данные), а если что-то пошло не так — выводится сообщение об ошибке, которое можно спрятать кнопкой «Закрыть». Если изменений нет — публикация не запускается.

> Сравнение цены: на сайте показывается «адаптированная» цена («Бесплатно» вместо «Вход свободный»). В данных хранится и исходный текст, и итоговая цена — сравнение идёт по исходным значениям, а итоговая проверяется дополнительно, чтобы смена формулировки без смены цены не перепорождала анонс.

> Под городом в левой колонке карточки есть маленькая ссылка-номер, ведущая на страницу события на «Элементах».

> На главной странице события разбиты по месяцам (заголовки месяцев) и календарным неделям (заголовки всех недель месяца, от понедельника; границы месяца подрезают первую и последнюю неделю; полностью прошедшие недели скрываются). Под заголовком недели — строка со счётчиками событий по дням (`17.09: 4. 18.09: —. …`). Слева — оглавление месяца→недели со ссылками внутри страницы. В подвале страницы — ссылки на памятку проекта и скиллы.

## 4а. Кнопка «Пост в Телеграм» на главной странице

Формирует черновик анонса для Телеграма по правилам из скилла `.opencode/skills/telegram-post/SKILL.md`:

1. Кнопка **«Пост в Телеграм»** в верхней панели открывает окно с двумя выпадающими списками дат: «С» — от первой даты с событиями, «По» — диапазон на 7 дней от выбранной начальной даты (так в анонсе не бывает одного и того же дня недели дважды). Рядом с датой — счётчик событий в скобках, например `17.09 (4)`.
2. Под датами сразу показывается готовый текст поста (по событиям из выбранного диапазона, по порядку дат и времени).
3. Кнопка **«Копировать»** — копирует текст в буфер обмена; **«Сформировать»** — пересчитывает пост после смены дат; **«Закрыть»** — закрывает окно.

Особенности текста поста:
- Три абзаца на событие: строка-шапка `ДД.ММ, ЧЧ:ММ, Город, Площадка (цена)`, строка авторов, строка `Название|ссылка` (с подзаголовком-лекторием в скобках, если он не повторяет площадку).
- Первая строка поста — «якорь»: `Научно-популярные лекции|https://elementy.ru/events?from=tg в <день>|<ссылка на день>, … и <день>|<ссылка на день>:`. Ссылка-«якорь» пишется на каждый из дней диапазона.
- В ценах показывается только нижняя граница: `от 4000 руб.` вместо `от 4000 до 10 000 руб.`; пробелы между группами цифр убираются (`10 000` → `10000`). Дополнительные записи (например, «онлайн») сохраняются.
- Длинные строки не режутся вручную: на сайте они просто переносятся на следующую строку (CSS), а в Телеграме перенесутся как надо.

## 5. Отправить изменения на GitHub (главный рабочий цикл)

После любых изменений (правил скрипты, обновил данные, поправил памятку):

```
git add -A
git commit -m "коротко: что изменилось"
git push
```

Каждый `git push` автоматически пересобирает сайт на GitHub и публикует его.

Готовый сайт в интернете: **https://kuzdr.github.io/Intensive_1/**

Полезные проверки:
```
git status          # какие файлы изменены, но ещё не записаны
git log --oneline   # история версий (коммитов)
```

## 6. Как устроен проект

```
C:\_PROJ\Zerocoder\Intensiv_1\
├── scrape.py                  # сбор данных с elementy.ru → данные
├── build.py                   # сборка сайта из данных
├── serve.py                   # локальный сервер (кнопка «Обновить данные»)
├── make_favicon.py            # пересоздание фавиконки (серая версия)
├── assets\favicon.ico         # фавиконка сайта (16/32/48)
├── .opencode\skills\          # навыки помощника (например, telegram-post — правила поста в Телеграм)
├── data\events.json           # ВСЕ события сайта (главный файл данных)
├── site\                      # готовый сайт (создаётся build.py)
│   ├── assets\img\            # фото лекторов (этот раздел хранится в git!)
│   ├── robots.txt             # запрет индексации сайта поисковиками
│   └── ...                     # остальное генерируется и в git не хранится
├── .github\workflows\deploy.yml  # автосборка и публикация на Pages
├── ПАМЯТКА.md                 # этот файл
└── .gitignore                 # список файлов, которые git не хранит
```

- `scrape.py` запускают редко (обновить список событий; при запуске сравнивает со старыми данными и помечает изменённое).
- `build.py` запускают после любых изменений данных или шаблонов.
- `serve.py` — самый частый способ работы: открывает сайт локально с рабочей кнопкой обновления.
- Сам репозиторий проекта: **https://github.com/Kuzdr/Intensive_1** (публичный).

## 7. Словарик простыми словами

| Термин | Что значит |
|---|---|
| **Репозиторий** | Проект с полной историей версий (обычно на GitHub) |
| **Коммит** | «Снимок» проекта в определённый момент; сохраняется навсегда |
| **Push** | Отправить свои коммиты на GitHub |
| **Ветка (branch)** | Отдельная линия разработки. Рабочая ветка проекта — `master` |
| **.gitignore** | Список файлов, которые НЕ отправляются на GitHub |
| **GitHub Pages** | Бесплатный хостинг статичных сайтов прямо из репозитория |
| **README.md** | Описание проекта, которое GitHub показывает на главной странице |
| **PATH** | Список папок, где Windows ищет программы. После установки программы терминал надо закрыть и открыть заново |

## 8. Если что-то не работает

- **«git не является внутренней или внешней командой»** — закрой терминал и открой новый (система не обновила PATH).
- **«python не является...»** — убедись, что пишешь `python`, а не `py`; если не помогает — скажи помощнику.
- Сборка ругается на русский текст «кракозябрами» — это нормально, это только вывод в консоль, файлы в порядке.
- Не понимаешь ошибку — просто скопируй её текст в диалог с opencode, помощник разберётся.

## 9. Куда движется проект (план)

1. Единая схема события + статусы (`upcoming / published / passed / rejected`).
2. Проверка новизны: что уже есть на elementy.ru (дедупликация).
3. Правила отбора событий «по стандартам Элементов».
4. Очередь ручного подтверждения спорных событий.
5. Адаптеры других источников (Архэ, ВСмысле, Medio Modo и т.д.) — регулярный автосбор.
6. Автопубликация обновлённого календаря (через тот же `git push`).

Каждый новый шаг этой плана будет добавляться в этот документ.
