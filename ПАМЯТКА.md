## 1. Как открыть терминал (PowerShell)

Самый простой способ:
1. Нажми **Win + R** (Win — клавиша с логотипом Windows).
2. Впиши `powershell` и нажми **Enter**.

Откроется окно с тёмным или синим фоном и строкой вида `PS C:\Users\mv>` — это и есть терминал.

> Совет: если нужно открыть терминал сразу в папке проекта — открой `C:\_PROJ\Zerocoder\Intensiv_1` в проводнике, кликни в адресную строку, сотри путь, напиши `powershell` и нажми Enter.

## 3. Как собрать сайт локально

В проекте три скрипта: **сбор данных**, **сборка сайта** и **локальный сервер**.

```
python scrape.py     # скачать события с elementy.ru → data/events.json
python build.py      # собрать сайт из данных → папка site/
python serve.py      # локальный сервер: http://localhost:8000
```

После сборки сайт можно открыть так:
```
Start-Process site\index.html
```
(или просто открой файл `C:\_PROJ\Zerocoder\Intensiv_1\site\index.html` двойным кликом).

## 4. Кнопка «Обновить данные» на главной странице

Работает только на **локальном сервере** (`python serve.py`, адрес http://localhost:8000). На публичной странице (GitHub Pages) кнопка вместо обновления покажет подсказку и дату/время последнего обновления данных.

Клик по кнопке открывает маленькое окно с вопросом **Да / Нет** — обновление запускается только после ответа «Да» (всё автоматически):
1. удаляются прошедшие события;
2. добавляются новые, которых ещё не было на сайте;
3. для уже имеющихся сравниваются основные поля (название, авторы, дата, лекторий, место, цена): если ничего не изменилось — описание сохраняется как было; если изменилось — описание перепорождается и событие помечается «обновлено»;
4. сайт пересобирается и изменения отправляются на GitHub (`git add -A`, `git commit`, `git push`) — публичная версия обновится сама.

После ответа «Да» окно закрывается само, а под кнопкой появляется служебная панель: линейка хода обновления с процентами. Когда всё готово, страница через пару секунд обновляется целиком (чтобы показать свежие данные), а если что-то пошло не так — выводится сообщение об ошибке, которое можно спрятать кнопкой «Закрыть». Если изменений нет — публикация не запускается.

> Сравнение цены: на сайте показывается «адаптированная» цена («Бесплатно» вместо «Вход свободный»). В данных хранится и исходный текст, и итоговая цена — сравнение идёт по исходным значениям, а итоговая проверяется дополнительно, чтобы смена формулировки без смены цены не перепорождала анонс.

> Под городом в левой колонке карточки есть маленькая ссылка-номер, ведущая на страницу события на «Элементах».

> На главной странице события разбиты по месяцам (заголовки месяцев) и календарным неделям (заголовки всех недель месяца, от понедельника; границы месяца подрезают первую и последнюю неделю; полностью прошедшие недели скрываются). Под заголовком недели — строка со счётчиками событий только по тем дням, на которые есть события (`17.09: 4. 18.09: 2. …`). Слева — оглавление месяца→недели со ссылками внутри страницы. В подвале страницы — ссылки на памятку проекта и скиллы.

## 4а. Кнопка «Пост в Телеграм» на главной странице

Формирует черновик анонса для Телеграма по правилам из скилла `.opencode/skills/telegram-post/SKILL.md`:

1. Кнопка **«Пост в Телеграм»** в верхней панели открывает окно с двумя выпадающими списками дат: «С» — от первой даты с событиями, «По» — диапазон на 7 дней от выбранной начальной даты (так в анонсе не бывает одного и того же дня недели дважды). Рядом с датой — счётчик событий в скобках, например `17.09 (4)`.
2. Под датами сразу показывается готовый текст поста (по событиям из выбранного диапазона, по порядку дат и времени).
3. Кнопка **«Копировать»** — копирует текст в буфер обмена; **«Сформировать»** — пересчитывает пост после смены дат; **«Закрыть»** — закрывает окно.

Особенности текста поста:
- Три абзаца на событие: строка-шапка `ДД.ММ, ЧЧ:ММ, Город, Площадка (цена)`, строка авторов, строка `Название|ссылка` (с подзаголовком-лекторием в скобках, если он не повторяет площадку).
- Первая строка поста — «якорь»: `Научно-популярные лекции|https://elementy.ru/events?from=tg в <день>|<ссылка на день>, … и <день>|<ссылка на день>:`. Ссылка-«якорь» пишется на каждый из дней диапазона.
- В ценах показывается только нижняя граница: `от 4000 руб.` вместо `от 4000 до 10 000 руб.`; пробелы между группами цифр убираются (`10 000` → `10000`). Дополнительные записи (например, «онлайн») сохраняются.
- Длинные строки не режутся вручную: на сайте они просто переносятся на следующую строку (CSS), а в Телеграме перенесутся как надо.

## 4б. Прототипы событий (черновики описаний)

Прототип — это черновик анонса для нового события, которого ещё нет на «Элементах». Прототипы видны на главной странице сайта рядом с обычными событиями, но **не попадают** в Телеграм-пост и в публикацию — это черновик для согласования.

Где лежат данные:
```
data\prototypes\<id>\prototype.json   # сам прототип (машиночитаемый)
data\prototypes\<id>\passport.txt     # памятка: все поля + HTML + заметки
data\prototypes\<id>\_proto_validate.txt  # текст + аудит проверок (nbsp, «ё»)
data\prototypes\_state.json           # скрытые прототипы, комментарии, обратная связь (файл появляется, когда состояние не пустое)
data\prototypes\_state.json.bak       # резервная копия состояния (создаётся автоматически при каждой записи)
data\prototypes\_archive\             # прототипы, уже опубликованные на «Элементах»
```

Что умеет интерфейс на главной странице (всё работает только на локальном сервере):
- **Фильтры** в модальном окне: месяц, лекторий, город, площадка, автор, тематика; поиск по названию и месту. Все фильтры применяются разом, счётчики событий видны в неделях.
- **Фильтр «Организаторы»** (вместо «Лектории» в блоке прототипов, 28.09.2026): показывает, откуда взята лекция — сайт организатора или аккаунт Timepad (например, `Санкт-Петербургский государственный университет`, `Фестиваль науки NAUKA 0+`). Название берётся из источника лекции, а не из подзаголовка. Фильтр работает только для карточек-прототипов.
- **Карточки прототипов**: кнопки «Скрыть» (в архив), «Комментарий», «Обратная связь», «Пересобрать описание», удаление.
- **Комментарий и обратная связь видны прямо в списке**, под текстом анонса (не надо открывать окно). Плашек «Есть комментарий» / «Есть обратная связь» на карточках больше нет.
- У показанного комментария и обратной связи есть **иконка «✕»** — удалить с подтверждением (наведение мышью показывает подсказку).
- **Страница прототипа**: формальные поля, описание и блок автора; для новых лекторов — поля 7.1–7.4 (инвертированное имя, стандартное имя, полное имя, описание автора) и фото 7.5/7.6 (если фото на источнике есть; чаще нет — тогда поле не заполняется).
- **Редактирование и копирование HTML** прямо на странице прототипа: у каждого значения две кнопки — карандаш (правка) и копирование. Если браузер не дал доступ к буферу, внизу сайта появляется подсказка «выделите код и нажмите Ctrl+C».
- Окна «Комментарий», «Обратная связь» и «Удалить» при открытии из списка показывают, к какому событию относятся: дата · автор · название.
- Перетаскивание и изменение размера модальных окон мышью.

Как выглядит дополнительная информация (стандарт, взятый с «Элементов»):
- Абзац об адресе начинается с `<b>Адрес:</b>`, внутри — организация, а за ней зал или номер аудитории.
- Дальше отдельной строкой `<b>Проезд:</b>` — только если в городе есть метро (в Орле этой строки нет).
- Ссылка на карту (Яндекс.Карты, в href — только параметр `text=`, пробелы обычные, не `%20`).
- Если на странице источника указан телефон — строка `<b>Телефон:</b>`.
- Строки внутри абзаца разделяются `<br>`.
- «Орел» пишется без «ё».

Шрифты на странице прототипа подобраны под «Элементы»: обычный абзац описания — 16 px, выдержка `blockquote.small` (цитата) — 15 px, абзац `p.small` (доп. информация, источники) — 13.5 px. Все три кегля разные, чтобы отличаться друг от друга.

Как выглядит страница прототипа (сверху вниз):
1. Хлебные крошки (в них ID прототипа — `прототип: <ID>`), заголовок и строка `ДД.ММ.ГГГГ · День недели · Время · Город`.
2. Формальные поля — компактной таблицей **до** описания, без номера поля, без заголовка «Формальные поля» и без пометок «только для справки»; значение показано так, как оно будет выглядеть на сайте («Название» → перенос строки, «Описание автора» → абзац), а HTML-код остаётся в кнопках копирования. Поле «ID события» в таблицу не выводится — ID и так виден в крошках; в `prototype.json` и в паспорте он остаётся.
3. Описание лекции, затем «Об авторе», затем «Дополнительная информация». Заголовков блоков, кроме «Об авторе», нет; пояснений под заголовками нет; нумерации абзацев («Абзац 1») нет.
4. Внизу — только ссылки на источники.

Кнопки на странице прототипа:
- Панели с кнопками **«Обновить данные»** и **«Пост в Телеграм»** на странице прототипа **нет** — эти кнопки нужны только на главной странице. На странице прототипа остаются только кнопки правки и копирования у полей, кнопки комментария/обратной связи/скрытия/удаления и ссылки на источники.
- У всех кнопок есть подсказка (наведение мышью): у кнопок правки — «Редактировать …», у кнопок копирования — «Скопировать …», у кнопки ID — «Скопировать ID источника: 4134142 (Timepad)».
- Кнопки правки и копирования прижаты вправо от своего значения.
- **У каждого источника свой набор кнопок** (строка `src-line`): карандаш (правка ссылки) и копирование. Если в ссылке есть числовой ID — добавляется третья кнопка **ID**, которая копирует только число. ID распознаётся у «Элементов» (`elementy.ru/events/<id>`), Timepad (`/event/<id>` и `timepad.ru/<id>`) и Архэ (`arche.ru/events/<id>`).
- Поле `9. Источники` выводится отдельной строкой на каждый источник, а не одной общей ячейкой.
- Под списком источников есть строка **«новый источник»** с кнопкой правки: вписать в неё ссылку и сохранить — источник добавится в конец списка. Чтобы удалить источник, откройте его правку и очистите поле (пустая строка = удалить).
- Правка списка источников синхронизирует формальное поле `9. Источники` в `prototype.json` — руками его править не нужно.
- На опубликованном сайте (GitHub Pages) кнопки правки автоматически скрываются, копирование остаётся.

Куда ведёт страница после действия (важно):
- **Сохранение** комментария, обратной связи, правки поля и **удаление прототипа** — возвращают в список прототипов: задача передана, событие можно закрыть.
- **Удаление** комментария или обратной связи (✕ у выведенного текста) и кнопка **«Скрыть»** — **остаются на странице события** и перезагружают её. Раньше эти действия уводили в список; теперь это исправлено, потому что событие обычно ещё правится.

Комментарии и обратная связь (`_state.json`) хранятся отдельно от `prototype.json`, поэтому переживают:
- пересборку сайта (`build.py`) и кнопку «Обновить данные»;
- архивирование прототипа — при возврате папки из `_archive` комментарий остаётся на месте;
- обрыв записи файла: `_state.json` пишется через временный файл, рядом лежит `_state.json.bak`, а если основной файл вдруг окажется битым, он переименовывается в `_state.json.broken` (ничего не пропадает молча), а комментарии берутся из резервной копии.

Блок «Об авторе»:
- **если автор есть на «Элементах»** — показывается **полноценный блок: фото, имя, описание** (без кнопок правки: копировать нечего, автор уже в базе);
- **если автор новый** — таблица полей 7.1–7.4 (инвертированное имя, стандартное имя, полное имя, описание автора) с кнопками правки и копирования, плюс фото, если оно есть на источнике.

Что решает, какой блок показать: флаг `"on_elementy"` у автора в `prototype.json`.
- `"on_elementy": true` — только если автора **реально нашли на «Элементах»** (тогда полный блок);
- `"on_elementy": false` или нет флага — новый автор, показываем поля 7.1–7.4.

Несколько авторов у одного события:
- в `prototype.json` пишем **список** `"authors": [ {...}, {...} ]`, а не объект `"author"`. Старый ключ `"author"` (один автор) тоже читается — совместимость сохранена;
- у каждого автора свой `"on_elementy"`, свой `photo` и свой `block_html`; блоки «Об авторе» идут по порядку в списке;
- в шапке страницы выводится строка `Автор: …` (один автор) или `Авторы: …` (несколько, через « и »);
- в шапке и в подписи к блокам имя показывается в форме `Имя Фамилия` (как в Elementy), а в тексте описания — в форме `Имя Фамилия` с выделением `<b><i>…</i></b>`;
- ключ правки полей автора — составной `индекс:номер`, например `0:7.1` для первого автора и `1:7.4` для второго (`protolib.parse_author_key`).

Где брать описание и фото автора, если он уже на «Элементах»: с любой страницы события «Элементов» с этим автором — блок «Об авторе» там уже собран. Проверено на событии 449969 (презентация книги «Мозг и его Я», 10.04.2026): оттуда взяты описания и фото Анохина и Черниговской. Фото кладутся в `photo` полным адресом (`https://elementy.ru/images/eltevents/…`).

Сам факт непустого `block_html` **не** означает, что автор есть на «Элементах»: `block_html` — это просто текст описания, он бывает заполнен у любого автора. Раньше решение принималось по нему, и новые авторы ошибочно показывались как «уже в базе», а стандартные поля 7.1–7.4 скрывались.

ГЛАВНОЕ ПРАВИЛО: ничего не выдумывать. В прототипе не должно быть НИ ОДНОГО факта, которого нет на источниках.
- Адрес, аудитория, телефон, метро и время пешком — только если это написано на источнике. Если источник про метро ничего не говорит — строку `<b>Проезд:</b>` не пишем (даже если метро в городе есть).
- Каждый источник в списке должен открываться (проверять HTTP-статус). Если ссылка даёт 404 — источник неверный: взять правильный URL с источника или из текста прототипа, а не оставлять старый.
- Если сомневаетесь, значение ставит **пользователь** — агент не догадывается.

Верхняя панель: переключатель показа, «Лектории», «Обновить данные» и «Пост в Телеграм» стоят в одну строку; надпись «Показывать» убрана, подписи сокращены («всё», ««Элементы»», «прототипы», «скрытые», «Лектории»).

Если кнопка не сработала и появилось сообщение «сервер запущен старой версией» — значит, на компьютере работает старый `serve.py`: закройте его и снова запустите `python serve.py`.

Незакрытые окна (защита от потери текста):
- Кнопка «Закрыть» в окне «Комментарий» и «Обратная связь», если внутри есть непустой текст (пробелы и переводы строк не считаются), спрашивает: «Закрыть без сохранения?» — «Отмена» возвращает к редактированию, «Закрыть без сохранения» выбрасывает правку.
- Пустой комментарий (только пробелы) закрывается сразу, без вопроса.
- **ESC** закрывает окно, если правок не было. Если правки есть, первый ESC ничего не закрывает и показывает подсказку «В окне несохранённые изменения: ESC ещё раз — закрыть без сохранения»; второй ESC закрывает.
- Удаление по иконке «✕» тоже спрашивает подтверждение.
- После сохранения обратной связи или комментария из окна события происходит возврат **в список** (окно открывалось со страницы прототипа — сохранили и ушли на главную).

Проверка перед показом любого прототипа (правило проекта, выполняется помощником):
1. `python -X utf8 tools\check_proto_json.py data\prototypes\<папка>\prototype.json` — детерминированная проверка САМОГО файла прототипа (nbsp, «ё», тире, инициалы, KLBLOCK, кавычки-лапки, поле 1 «Привязка», римские цифры, буквенные сокращения, сырой пробел U+00A0). Без пути — проверяются все прототипы сразу.
2. Скилл `proofreading` — письменный аудит всех «ё» и всех nbsp в файл прототипа (секция `АУДИТ` в `_proto_validate.txt`).
3. Скилл `post-check` — финальный чек-лист из 16 пунктов (в пункте 9a — лапки `„…“` только внутри ёлочек `«…»`; без внешних кавычек кавычки должны быть ёлочками; в пункте 13 — сверка поля 1 «Привязка» с датой и временем).

Два правила, которые легко забыть (записаны 28.09.2026 по правкам СПбГУ):
- неразбиваемый пробел в файле прототипа пишется **только текстом `&nbsp;`**; сырой символ неразбиваемого пробела в данных запрещён;
- пробелы источника не образец: nbsp ставится и убирается по правилам, проверяется в обе стороны (и лишние, и забытые).

Новые прототипы добавляются копированием папки и правкой `prototype.json`; `build.py` подхватывает их сам.

## 5. Отправить изменения на GitHub (главный рабочий цикл)

После любых изменений (правил скрипты, обновил данные, поправил памятку):

```
git add -A
git commit -m "коротко: что изменилось"
git push
```

Перед `git commit` обязательно проверяется, что все навыки (скиллы) в
порядке — это делает скрипт:
```
python -X utf8 tools\check_skills.py
```
Если он написал «РЕЗУЛЬТАТ: все скиллы валидны» — можно коммитить. Если
найдены проблемы — их надо сначала исправить и прогнать проверку заново.
Эта же проверка прогоняется после запуска проекта / открытия новой
сессии — чтобы убедиться, что все скиллы загрузились нормально.

Каждый `git push` автоматически пересобирает сайт на GitHub и публикует его.

Готовый сайт в интернете: **https://kuzdr.github.io/Intensive_1/**

Полезные проверки:
```
git status          # какие файлы изменены, но ещё не записаны
git log --oneline   # история версий (коммитов)
```

│   └── html_to_text.py          # перевод HTML в текст

│   ├── telegram-post\         #   правила поста в Телеграм
│   ├── event-description\     #   описания событий по источникам (ИИ)
│   │   └── reference\lists\   #   справочные списки для полей описаний:
│   │                          #     type/audience/place/lectorium/theme.md
│   ├── proofreading\          #   корректорские правила (ё, пробелы и т.п.)
│   └── post-check\            #   финальная проверка готового описания
├── data\events.json           # ВСЕ события сайта (главный файл данных)
├── data\prototypes\           # прототипы (черновики) событий — см. раздел 4б
├── site\                      # готовый сайт (создаётся build.py)
│   ├── assets\img\            # фото лекторов (этот раздел хранится в git!)
│   ├── robots.txt             # запрет индексации сайта поисковиками
│   └── ...                     # остальное генерируется и в git не хранится
├── .github\workflows\
│   ├── deploy.yml               # автосборка и публикация на Pages
│   └── update-admin-lists.yml   # ежедневное обновление списков описаний событий
├── ПАМЯТКА.md                 # этот файл

- `scrape.py` запускают редко (обновить список событий; при запуске сравнивает со старыми данными и помечает изменённое).
- `build.py` запускают после любых изменений данных или шаблонов.
- `serve.py` — самый частый способ работы: открывает сайт локально с рабочей кнопкой обновления.
- `protolib.py` — «библиотека» прототипов (раздел 4б): читает `data\prototypes\`, скрывает и восстанавливает прототипы, правит HTML описания, ищет дубли среди событий «Элементов» (совпадение по ссылке или по длинному названию) и удаляет прототип, когда событие появилось на «Элементах». Вызывается из `build.py` и `serve.py`.
- `tools\check_proto_json.py` — проверка прототипа по самому файлу `prototype.json` (формальные поля, заголовок, аннотация, текст лектора, HTML описаний, «Дополнительная информация», авторы) — запускается помощником перед показом каждого прототипа. Команда: `python -X utf8 tools\check_proto_json.py data\prototypes\<папка>\prototype.json` (без пути — все прототипы).
- `tools\check_prototype.py` — сама детерминированная проверка механики текста (nbsp, «ё», тире, кавычки, римские цифры, буквенные сокращения, поле 1 «Привязка»). Вызывается из `check_proto_json.py`; можно запускать и напрямую с текстовым файлом. Проверка «ё» идёт и по списку слов `tools\yo_words.txt` (где «ё» может быть пропущена).
- `tools\fix_nbsp_entities.py` — разовая замена сырых неразбиваемых пробелов (U+00A0) в `data\prototypes\*\prototype.json` на текст `&nbsp;`. Запускать вручную не нужно: `protolib.py` и так приводит данные к этому виду при каждом сохранении.
- `tools\check_skills.py` — проверка валидности всех скиллов (YAML-frontmatter парсится настоящим YAML-парсером, пути из скиллов существуют) — запускается перед каждым коммитом и после запуска проекта / открытия новой сессии (правило проекта).
- `tools\update_admin_lists.py` — обновляет справочные списки описаний событий в `.opencode\skills\event-description\reference\lists\` (типы, аудитории, места проведения, лектории, тематики). Данные берутся со страницы события на «Элементах» (на главной /events списки неполные). Обновление мест по расписанию выполняется автоматически раз в день через `.github\workflows\update-admin-lists.yml`; вручную команда `python -X utf8 tools\update_admin_lists.py`.
- Сам репозиторий проекта: **https://github.com/Kuzdr/Intensive_1** (публичный).

## 7. Словарик простыми словами

| Термин | Что значит |
|---|---|
| **Репозиторий** | Проект с полной историей версий (обычно на GitHub) |
| **Коммит** | «Снимок» проекта в определённый момент; сохраняется навсегда |

| **.gitignore** | Список файлов, которые НЕ отправляются на GitHub |
| **GitHub Pages** | Бесплатный хостинг статичных сайтов прямо из репозитория |
| **README.md** | Описание проекта, которое GitHub показывает на главной странице |
| **PATH** | Список папок, где Windows ищет программы. После установки программы терминал надо закрыть и открыть заново |

## 8. Если что-то не работает

- **«git не является внутренней или внешней командой»** — закрой терминал и открой новый (система не обновила PATH).
- **«python не является...»** — убедись, что пишешь `python`, а не `py`; если не помогает — скажи помощнику.
- Сборка ругается на русский текст «кракозябрами» — это нормально, это только вывод в консоль, файлы в порядке.
- Не понимаешь ошибку — просто скопируй её текст в диалог с opencode, помощник разберётся.
