## 1. Как открыть терминал (PowerShell)

Самый простой способ:
1. Нажми **Win + R** (Win — клавиша с логотипом Windows).
2. Впиши `powershell` и нажми **Enter**.

Откроется окно с тёмным или синим фоном и строкой вида `PS C:\Users\mv>` — это и есть терминал.

> Совет: если нужно открыть терминал сразу в папке проекта — открой `C:\_PROJ\Zerocoder\Intensiv_1` в проводнике, кликни в адресную строку, сотри путь, напиши `powershell` и нажми Enter.

## 3. Как собрать сайт локально

В проекте три скрипта: **сбор данных**, **сборка сайта** и **локальный сервер**.

```
python scrape.py     # скачать события с elementy.ru → data/events.json
python build.py      # собрать сайт из данных → папка site/
python serve.py      # локальный сервер: http://localhost:8000
```

После сборки сайт можно открыть так:
```
Start-Process site\index.html
```
(или просто открой файл `C:\_PROJ\Zerocoder\Intensiv_1\site\index.html` двойным кликом).

## 4. Кнопка «Обновить данные» на главной странице

Работает только на **локальном сервере** (`python serve.py`, адрес http://localhost:8000). На публичной странице (GitHub Pages) кнопка вместо обновления покажет подсказку и дату/время последнего обновления данных.

> **ВАЖНО: после правки `serve.py` или `protolib.py` сервер надо перезапускать.**
> `python serve.py` загружает код один раз при старте. Если сервер запущен
> заранее (например, 27.09), то все ваши новые возможности в нём просто
> отсутствуют: страница ведёт себя «как раньше» и кажется, что ничего не
> изменилось. Так было 29.09 — обновление отработало старым кодом и написало
> «Изменений нет», хотя новое было.
> Правки `build.py` перезапуска НЕ требуют: скрипт сборки запускается
> отдельным процессом при каждом обновлении, поэтому его изменения применяются
> при следующем нажатии «Обновить» (правило 02.10.2026).
> **Как перезапустить:** в окне, где запущен сервер, нажмите `Ctrl+C`
> (в Windows консоль спросит `Terminate batch job (Y/N)?` — введите `Y`),
> затем снова наберите `python serve.py`.
> Если забудете перезапустить, об этом скажет и страница (жёлтое
> предупреждение под кнопкой: «ВНИМАНИЕ: сервер запущен до последних
> правок»), и само окно сервера (красные строки при старте).

Клик по кнопке открывает маленькое окно с вопросом **Да / Нет** — обновление запускается только после ответа «Да» (всё автоматически):
1. **сначала прототипы** — самый быстрый и самый важный этап, поэтому он
   идёт первым (числа «События: 51 · Прототипы: 11» видны сразу, до всякой
   загрузки с сайта);
2. **явный проход по прототипам**: сервер идёт по каждому прототипу и по каждой строке сообщает два факта:
   - **изменился ли** он с прошлого обновления — «ИЗМЕНЁН» или «без изменений»;
   - **что с ним сейчас**: «в списке на сайте», «скрыт вами», «скрыт: такая же лекция уже стоит на «Элементах» (ID 450636)» — то есть лекция уже поставлена и прототип спрятан автоматически, — либо «перенесён в архив (лекция уже прошла)».
   В консоли сервера это видно построчно, в панели под кнопкой — бегущей строкой («Проход по прототипам (3 из 11): 0+-261006-Gerasimov — скрыт: такая же лекция уже стоит на «Элементах»…»), а по окончании — полным списком. В конце прохода числа уточняются (прошедшие лекции уходят в архив, поэтому итог может отличаться от первого).
3. удаляются прошедшие события;
4. добавляются новые, которых ещё не было на сайте;
5. для уже имеющихся сравниваются основные поля (название, авторы, дата, лекторий, место, цена): если ничего не изменилось — описание сохраняется как было; если изменилось — описание перепорождается и событие помечается «обновлено»;
6. сайт пересобирается и изменения отправляются на GitHub (`git add -A`, `git commit`, `git push`) — публичная версия обновится сама. В коммит попадает весь проект: события, прототипы (`data/prototypes/`), правки скриптов и навыков.

### Счётчик виден сразу, в начале обновления

Как только вы нажали «Да», над полосой прогресса появляется счётчик — он виден всё время обновления:

```
События: 51 · Прототипы: 11 — начинаем обновление: сначала прототипы
События: 51 · Прототипы: 11 (изменено 0) — прототипы проверены, переходим к событиям
События: 52 (новых 1, изменено 0, удалено 0) · Прототипы: 11 (изменено 0) — события собраны, собираем сайт
События: 52 (новых 1, изменено 0, удалено 0) · Прототипы: 11 (изменено 0)
```

Числа берутся из файлов проекта (`data/events.json` и папки `data/prototypes/`), поэтому появляются мгновенно — не надо ждать конца сбора. По ходу обновления к ним добавляются итоги: сколько событий добавлено, изменено и удалено, сколько прототипов изменилось.

### Статистика обновления

Итоговая панель под кнопкой состоит из двух блоков — по событиям и по прототипам:

```
СОБЫТИЯ «ЭЛЕМЕНТЫ»
Всего в календаре: 51
Добавлено: 1   Изменено: 0   Удалено: 0

ПРОТОТИПЫ (проход: всего 11)
Проверено: 11   показано: 7   скрыто: 4 (вами: 2, лекция уже стоит на «Элементах»: 2)   в архиве: 0
Изменено с прошлого обновления: нет — все прототипы те же, что уехали на GitHub

Проход по прототипам:
  0+-261006-Budanov — скрыт вами (без изменений)
  0+-261006-Gerasimov — скрыт: такая же лекция уже стоит на «Элементах» (ID 450636: название, автор, ссылка на источник) (без изменений)
  …
```

Та же статистика записывается в `data/update_report.json` (поля `protos` и `protos_pass`) — то есть остаётся в файле, а не только на экране. Сообщение коммита её тоже содержит: `Автообновление данных: +1 новых, 0 изменено, 0 удалено; прототипов: 11, не изменились; скрыто 4 (вами 2, дублей «Элементов» 2)`.

Что значит «изменился прототип»: сравнивается не время правки файла, а **размер и содержимое** (`prototype.json` и `_state.json`). Время изменения не годится для сравнения — оно меняется у всех файлов разом при копировании проекта или `git checkout`, и тогда «изменёнными» оказываются все прототипы сразу. По той же причине переносы строк (CRLF на вашем компьютере, LF на сервере) правкой прототипа не считаются. Состояние на момент последней успешной публикации хранится в служебном файле `data/proto_stamp.json` (в Git попадает, пересоздаётся сам).

Если ни события, ни прототипы с прошлого обновления не менялись, сайт **не пересобирается и на GitHub ничего не отправляется** — так появится сообщение «Изменений нет — ни события, ни прототипы не менялись с прошлого обновления». Если прототип менялся (например, вы правили описание) — пересборка и публикация будут, и в сообщении коммита будет «прототипов: 11, изменено: 1 (TP-…)».

### Результат не пропадает

После успешного обновления страница перечитывается целиком (чтобы показать свежие данные), а панель с результатом **запоминается** и появляется снова — с заголовком «ПОСЛЕДНЕЕ ОБНОВЛЕНИЕ (дата и время)». Статистику можно спокойно прочитать после перезагрузки; кнопка «Закрыть» убирает панель, и запоминание сбрасывается.

### Скрытые прототипы не восстанавливаются

Кнопка «Скрыть» на карточке прототипа записывает пометку в файл `data/prototypes/_state.json`. Файл лежит в Git — поэтому скрытые прототипы скрыты и на публичной версии сайта, а не только у вас на компьютере. Чтобы скрытие не потерялось при обновлении, перед публикацией работает проверка-охрана:

- если файл состояния не читается (повреждены и `_state.json`, и его резервная копия) — публикация **отменяется**: сообщение объясняет, что скрытые прототипы вернулись бы в список;
- если за время обновления скрытие пропало (было скрыто — стало видно) — публикация **отменяется**, и в сообщении названы именно такие прототипы;
- если `data/prototypes/_state.json` случайно попадёт в `.gitignore` — обновление остановится с предупреждением: без этого файла публичная версия соберётся без скрытых прототипов.

Вернуть прототип в список можно только осознанно — кнопкой «Восстановить» на его карточке.

> Кнопка **«Перезагрузить с «Элементов»**» на странице события тоже публикует результат на GitHub: скачивает событие с «Элементов», пересобирает сайт и делает коммит с сообщением «Перезагрузка с «Элементов»: обновлено событий: N». Раньше она только пересобирала сайт локально, и правка оставалась на компьютере — теперь уезжает на публичную версию. Если на «Элементах» ничего не изменилось, публикации не будет — это нормально.

После ответа «Да» окно закрывается само, а под кнопкой появляется служебная панель: линейка хода обновления с процентами. Когда всё готово, страница через пару секунд обновляется целиком (чтобы показать свежие данные), а если что-то пошло не так — выводится сообщение об ошибке, которое можно спрятать кнопкой «Закрыть».

> Сравнение цены: на сайте показывается «адаптированная» цена («Бесплатно» вместо «Вход свободный»). В данных хранится и исходный текст, и итоговая цена — сравнение идёт по исходным значениям, а итоговая проверяется дополнительно, чтобы смена формулировки без смены цены не перепорождала анонс.

> Под городом в левой колонке карточки есть маленькая ссылка-номер, ведущая на страницу события на «Элементах».

> На главной странице события разбиты по месяцам (заголовки месяцев) и календарным неделям (заголовки всех недель месяца, от понедельника; границы месяца подрезают первую и последнюю неделю; полностью прошедшие недели скрываются). Под заголовком недели — строка со счётчиками событий только по тем дням, на которые есть события (`17.09: 4. 18.09: 2. …`). Слева — оглавление месяца→недели со ссылками внутри страницы. В подвале страницы — ссылки на памятку проекта и скиллы.

## 4а. Кнопка «Пост в Телеграм» на главной странице

Формирует черновик анонса для Телеграма по правилам из скилла `.opencode/skills/telegram-post/SKILL.md`:

1. Кнопка **«Пост в Телеграм»** в верхней панели открывает окно с двумя выпадающими списками дат: «С» — от первой даты с событиями, «По» — диапазон на 7 дней от выбранной начальной даты (так в анонсе не бывает одного и того же дня недели дважды). Рядом с датой — счётчик событий в скобках, например `17.09 (4)`.
2. Под датами сразу показывается готовый текст поста (по событиям из выбранного диапазона, по порядку дат и времени).
3. Кнопка **«Копировать»** — копирует текст в буфер обмена; **«Сформировать»** — пересчитывает пост после смены дат; **«Закрыть»** — закрывает окно.
4. Чек-бокс **«HTML»** рядом с датами переключает вид поста:
   - **выключен** (по умолчанию) — обычный текст: жирный шрифт звёздочками `**Автор**`, ссылка как `Название|URL` (адрес виден прямо в тексте);
   - **включён** — пост в формате HTML (`<p>`, `<br>`, `<b>`, `<a href="…">`), причём в окне он показывается **как готовый пост**, а не как код. У всех абзацев, кроме последнего, в конце стоит `<br>&nbsp;` — без этого при копировании в Телеграм лекции слипаются без пустых строк. Кнопка «Копировать» в этом режиме копирует фрагмент так же, как если бы вы выделили текст мышью в браузере: в буфер попадают и разметка, и обычный текст, поэтому жирный шрифт и ссылки остаются живыми при вставке.
   Выбор запоминается в браузере и остаётся при следующем открытии окна. Остальное — даты, три строки на лекцию, цены, пустые строки между лекциями — в обоих режимах одинаковое.

Особенности текста поста:
- Три абзаца на событие: строка-шапка `ДД.ММ, ЧЧ:ММ, Город, Площадка (цена)`, строка авторов, строка `Название|ссылка` (с подзаголовком-лекторием в скобках, если он не повторяет площадку).
- «ОНЛАЙН» всегда в конце шапки, без запятой перед «и»: событие «в зале и онлайн» — `ДД.ММ, ЧЧ:ММ, Москва, Площадка (цена) и ОНЛАЙН`; событие **полностью онлайн** — `ДД.ММ, ЧЧ:ММ, ОНЛАЙН (цена)`, а площадка переезжает в скобки после названия (`(курс. Площадка)`, отделяется точкой; развёрнутое название — из `PLACE_FULL` в `build.py`). Логика: `post_place`/`post_subtitle_with_place` в `build.py`, собранные данные — в `site\js\post.js`.
- Первая строка поста — «якорь»: `Научно-популярные лекции|https://elementy.ru/events?from=tg в <день>|<ссылка на день>, … и <день>|<ссылка на день>:`. Ссылка-«якорь» пишется на каждый из дней диапазона.
- В ценах показывается только нижняя граница: `от 4000 руб.` вместо `от 4000 до 10 000 руб.`; пробелы между группами цифр убираются (`10 000` → `10000`). Дополнительные записи (например, «онлайн») сохраняются.
- На ВДНХ павильон в данных стоит в скобках (`ВДНХ (ИМК «Буран»)`); в посте скобки павильона заменяем запятой, чтобы не было двух скобок подряд: `03.10, 15:00, Москва, ВДНХ (центр «Космонавтика и авиация») (бесплатно)` → `03.10, 15:00, Москва, ВДНХ, центр «Космонавтика и авиация» (бесплатно)`. Правило только для ВДНХ.
- Длинные строки не режутся вручную: на сайте они просто переносятся на следующую строку (CSS), а в Телеграме перенесутся как надо.

## 4б. Прототипы событий (черновики описаний)

Прототип — это черновик анонса для нового события, которого ещё нет на «Элементах». Прототипы видны на главной странице сайта рядом с обычными событиями, но **не попадают** в Телеграм-пост и в публикацию — это черновик для согласования.

Где лежат данные:
```
data\prototypes\<id>\prototype.json   # сам прототип (машиночитаемый)
data\prototypes\<id>\passport.txt     # памятка: все поля + HTML + заметки
data\prototypes\<id>\_proto_validate.txt  # текст + аудит проверок (nbsp, «ё»)
data\prototypes\_state.json           # скрытые прототипы, комментарии, обратная связь (файл появляется, когда состояние не пустое)
data\prototypes\_state.json.bak       # резервная копия состояния (создаётся автоматически при каждой записи)
data\prototypes\_archive\             # прототипы, уже опубликованные на «Элементах»
```

Что умеет интерфейс на главной странице (всё работает только на локальном сервере):
- **Фильтры** в модальном окне: месяц, лекторий, город, площадка, автор, тематика; поиск по названию и месту. Все фильтры применяются разом, счётчики событий видны в неделях.
- **Фильтр «Организаторы»** (вместо «Лектории» в блоке прототипов, 28.09.2026): показывает, откуда взята лекция — сайт организатора или аккаунт Timepad (например, `Санкт-Петербургский государственный университет`, `Фестиваль науки NAUKA 0+`). Название берётся из источника лекции, а не из подзаголовка. Фильтр работает только для карточек-прототипов.
- **Карточки прототипов**: кнопки «Скрыть» (в архив), «Комментарий», «Обратная связь», «Пересобрать описание», удаление.
- **Комментарий и обратная связь видны прямо в списке**, под текстом анонса (не надо открывать окно). Плашек «Есть комментарий» / «Есть обратная связь» на карточках больше нет.
- У показанного комментария и обратной связи есть **иконка «✕»** — удалить с подтверждением (наведение мышью показывает подсказку).
- **Страница прототипа**: формальные поля, описание и блок автора; для новых лекторов — поля 7.1–7.6 (инвертированное имя, стандартное имя, полное имя, описание автора, фото 7.5 — если есть на источнике, файл фотографии 7.6 — всегда).
- **Редактирование и копирование HTML** прямо на странице прототипа: у каждого значения две кнопки — карандаш (правка) и копирование. Правка работает и на локальном сервере, и на опубликованном сайте (GitHub Pages): на localhost «Сохранить» пишет значение в файл прототипа и пересобирает сайт, на публичной версии — запоминает правку в браузере до следующего обновления сайта (см. «Кнопки на странице прототипа»). Если браузер не дал доступ к буферу, внизу сайта появляется подсказка «выделите код и нажмите Ctrl+C».
- **В окне правки и при копировании неразбиваемые пробелы сохраняются текстом `&nbsp;`** (исправлено 30.09.2026): значение кнопок правки/копирования берётся из атрибута `data-text`, который раньше превращал `&nbsp;` в «сырой» символ U+00A0 — в окне он выглядел как обычный пробел, а при вставке терялся. Теперь в окне правки видно `&nbsp;` (как в `prototype.json`), и при копировании они не теряются. HTML-код в data-text экранируется обычным способом (`esc_nbsp_text` в build.py).
- **Списки — отдельной строкой на каждый элемент (01.10.2026)**: если в поле 9 «Источники», в поле 10 «URL регистрации/покупки билета» или в «Доп.информации» несколько элементов, на странице прототипа каждый из них — **отдельная строка таблицы со своей кнопкой правки и своим «скопировать»** (раньше все ссылки поля 10 сливались в одну ячейку и одну кнопку). У поля 10 под первой строкой появляется строка «Добавить ссылку» (`+ Добавить`); у «Доп.информации» — кнопка «Добавить абзац» в конце таблицы. Удаление — пустой строкой в окне правки. Кнопки «id источника» у полей 9/10 работают так же, как раньше. Разметка: `.ftable-src-row`, `.ftable-reg-row`, `.exrow` в `build.py`.
- **Подписи у ссылок на регистрацию — `reg_labels`** (01.10.2026): в таблице поля 10 слева от ссылки показывается, что это за билет («билет на лекцию», «билет на онлайн-трансляцию»). Подписи лежат в `prototype.json` верхнего уровня в поле `reg_labels` — по порядку ссылок, столько же, сколько ссылок. Это **только подпись для чтения**: в значение поля 10, в буфер обмена и в «Элементы» она не попадает; при удалении ссылки подписи сдвигаются. Подписи берём из «Доп.информации», а не придумываем.
- **Счётчик «Сейчас на странице»** (01.10.2026): на главной, сразу под вступлением, всегда показано, сколько на странице событий и сколько прототипов («Сейчас на странице: 66 событий, 40 прототипов»). Нет прототипов — про них не пишем, нет событий — не пишем про события, нет ни того, ни другого — строка не выводится совсем. Считается **живо**: пересчёт идёт при каждой смене фильтров (режим/скрытые/организаторы) и при правке прототипа на странице, потому что значение из файла после фильтрации становится неверным. Разметка: `.tally` в CSS, `tally_html()`/`ru_plural()` в `build.py` (строка при сборке), `setTally()`/`plural()` в `build_prototypes_js()` (пересчёт на странице, вызов из `applyFilter`).
- Окна «Комментарий», «Обратная связь» и «Удалить» при открытии из списка показывают, к какому событию относятся: дата · автор · название.
- Перетаскивание и изменение размера модальных окон мышью.

Как выглядит дополнительная информация (стандарт, взятый с «Элементов»):
- **СНАЧАЛА ищем образцы на «Элементах»** (правило пользователя 29.09.2026): для каждого нового лектория и/или новой площадки находим опубликованные события этого организатора и берём у них набор и порядок блоков, формулировки, выделения `<b>`, разделитель `<!-- @@@ -->`, класс `small`, название площадки в шапке (в том числе с аббревиатурой), адрес, проезд, карту, сайт площадки и контакты — в том числе те, которых нет в источнике (это сведения о площадке, а не о событии). Образец: лекция 450571 для лектория «Medio Modo» на БЕН РАН. Найденное закрепляем в карточке лектория `.opencode\skills\event-description\reference\lectories.md` и в скилле (разд. 5а, «Образцы… по лекториям»). Телефон приводим к общему формату `+7(999)999-99-99`, даже если в образце он написан иначе.
- **Разделитель <!-- @@@ -->** — общий элемент доп. информации, который ставится **непосредственно перед блоком ссылок**, то есть перед абзацем «Информация о лекции на сайте …» (class="small"). Он нужен для дела, а не для красоты: когда новое описание собирается копированием старого, по этой метке сразу видно, где надо поменять ссылку на источник. Поэтому перед блоком «Контакты организатора» его не ставим (так он стоит на опубликованной странице 450571 лектория «Medio Modo»).
- Абзац об адресе начинается с `<b>Адрес:</b>`, внутри — организация, а за ней зал или номер аудитории.
- Дальше отдельной строкой `<b>Проезд:</b>` — только если в городе есть метро (в Орле этой строки нет).
- Ссылка на карту (Яндекс.Карты, в href — только параметр `text=`, пробелы обычные, не `%20`).
- Если на странице источника указан телефон — строка `<b>Телефон:</b>`.
- Строки внутри абзаца разделяются `<br>`.
- «Орел» пишется без «ё».
- В аннотации и в первом абзаце описания НЕТ ссылок-приглашений («узнай больше на сайте организатора», «подробнее на Timepad»): все ссылки — в дополнительной информации (после `<!-- @@@ -->`) и в полях 9 и 10.

Шрифты на странице прототипа подобраны под «Элементы»: обычный абзац описания — 16 px, выдержка `blockquote.small` (цитата) — 15 px, абзац `p.small` (доп. информация, источники) — 13.5 px. Все три кегля разные, чтобы отличаться друг от друга.

### Правило важнее старого образца (правило 30.09.2026)

Опубликованная страница «Элементов» — это образец ВО оформления (что где и как), но НЕ источник правил. Если образец противечит действующему правилу — пишем по правилу, как было у явного решения. И если правило однозначно — вопрос пользователю не задаём: в блоке адреса пишем **«Проезд: метро «…»»** — без «до станции метро «…»», даже если так написано в старом опубликованной лекции. Возраст и аннотация — только в фолде 12.

И ещё одно обязательное правило: если правило однозначно — вопрос не задаём.

Если нужный блок уже готов на «Элементах» (описание автора в базе, подзаголовок лектория и т.п.), действует **простое правило: вырезать код и вставить его в описание**. Никаких «примерок» типографики и повторных согласований ради неразбиваемых пробелов и «ё»: готовое оформление «Элементов» и есть эталон.

Как это оформлено технически:
- в `prototype.json` есть поле верхнего уровня `verbatim_fragments` — массив строк с дословными вставками (обычно их две: форма именительного падежа для блока автора и поля 7.4, и та же формулировка, вписанная в предложение аннотации);
- валидатор `tools\check_prototype.py` по этому полю ПРОПУСКАЕТ проверки nbsp, «ё» и тире внутри фрагментов — готовое оформление не ломается;
- **режим `--fix` фрагменты тоже не трогает** (исправлено 29.09.2026: он вставлял nbsp внутрь готового блока «Об авторе» и ломал дословность; регрессия закреплена в `tools\check_skills.py`);
- фрагмент должен совпадать с текстом в прототипе **побайтово** (регистр, пробелы, `&nbsp;`) — иначе вхождение не находится и правила сработают как обычно. Если один и тот же блок вставлен в разных формах, вносим каждую форму отдельным элементом;
- на собственные тексты прототипа (шапка, аннотация, доп. информация, формальные поля) правило не распространяется: там действуют все обычные правила.

Если автор УЖЕ есть на «Элементах», его блок «Об авторе» берём оттуда (фото, имя, описание — дословно) и **стандартное** bio «Элементов» в тексте описания полностью **не дублируем**: на «Элементах» оно живёт в отдельном блоке «Об авторе» (на сайте это заглушка `<KLBLOCK eltclub_authors_about/>`). Но **описание автора ИЗ ИСТОЧНИКА** — это другое описание, и оно в тексте остаётся: если организатор даёт его отдельным блоком «О лекторе», а лектор в тексте лекции не упомянут, добавляем в конце аннотации (последним абзацем внутри `</blockquote>`) закрывающий абзац «Лекцию прочитает <b><i>Имя Фамилия</i></b> — <i>описание из источника</i>.» (уже без «прочитает», если лектор назван в первом абзаце). Расхождения между источником и «Элементами» тут нормальны и не правятся.

Подробности — в скиллах: `event-description` разд. 3г, `proofreading` (раздел «Готовые блоки с «Элементах» — исключение из чек-листа»).

Абзац с представлением автора («Лекцию прочитает <b><i>Имя Фамилия</i></b> — <i>должность</i>», «Экскурсию проведёт…») ставится **в конце аннотации, последним абзацем** — не в начале (уточнение пользователя 30.09.2026).

### Если автора нет, а он обязателен (правило пользователя 30.09.2026)

У лекции, экскурсии-лекции, лекции-концерта, мастер-класса автор **должен быть**. Если источник его не называет (например, пишет только «от эксперта павильня „Космос“» или «лектор будет объявлен позже»), такое событие **нельзя выносить на сайт без вашего подтверждения**.

Что делаем:
1. Ищем автора обязательно: страница мероприятия и афиша на сайте организатора, вторая страница события, новости и пресс-релизы, афиша-агрегаторы, соцсети организатора. Где искали — пишем в `notes`.
2. Нашли — вносим как обычно (блок «Об авторе»).
3. Не нашли — в `notes` пишем **«АВТОР НЕ УСТАНОВЛЕН — публикация только после подтверждения пользователя»**, поле `lecturer` оставляем пустым, `authors: []`, заглушку `<KLBLOCK eltclub_authors_about/>` НЕ вставляем.
4. Обязательно задаём вам вопрос: публиковать без автора или сначала уточнить его у организатора.
5. Никогда не подставляем «похожего» сотрудника той же площадки и не выдаём «эксперта павильона» за имя автора.

Такое событие нельзя показывать как готовое к публикации.

### Дубли: уже опубликованное на «Элементах» — не плодим (правило пользователя 30.09.2026)

Если событие уже вышло на «Элементах» (вы его поставили сами или оно там было раньше), прототип **не нужен на сайте вообще** — прячем его через кнопку «Скрыть» с пометкой вида `ДУБЛЬ: событие уже опубликовано на «Элементах» (450659, …)`. Держать такой прототип в списке нельзя даже «на будущее»: дубль — это дубль. Скрытые прототипы не восстанавливаются.

**Сверка идёт по полному списку `elementy.ru/events` БЕЗ параметров** (там всегда все предстоящие события) — тем же способом, что и `scrape.py`; не по локальному `data/events.json` (~60 ближайших) и не по похожему заголовку. Скрипт `tools\check_elementy_by_date.py` выгружает список и печатает совпадения по дате: **дубль = совпадение даты**, а не похожего названия (ЗИЛ, 01.10.2026: 450590 и Timepad 4208440 — одна и та же лекция; 12.11.2026 у Корнейчика дубля на «Элементах» не было, хотя тот же доклад уже выходил 24.09.2026 — это другое событие).

Как выглядит страница прототипа (сверху вниз):
1. Хлебные крошки (в них ID прототипа — `прототип: <ID>`), заголовок и строка `ДД.ММ.ГГГГ · День недели · Время · Город`.
2. Формальные поля — компактной таблицей **до** описания, без номера поля, без заголовка «Формальные поля» и без пометок «только для справки»; значение показано так, как оно будет выглядеть на сайте («Название» → перенос строки, «Описание автора» → абзац), а HTML-код остаётся в кнопках копирования. Поле «ID события» в таблицу не выводится — ID и так виден в крошках; в `prototype.json` и в паспорте он остаётся.
3. Описание лекции, затем «Об авторе», затем «Дополнительная информация». Заголовков блоков, кроме «Об авторе», нет; пояснений под заголовками нет; нумерации абзацев («Абзац 1») нет.
4. Внизу — только ссылки на источники.

Кнопки на странице прототипа:
- Панели с кнопками **«Обновить данные»** и **«Пост в Телеграм»** на странице прототипа **нет** — эти кнопки нужны только на главной странице. На странице прототипа остаются только кнопки правки и копирования у полей, кнопки комментария/обратной связи/скрытия/удаления и ссылки на источники.
- У всех кнопок есть подсказка (наведение мышью): у кнопок правки — «Редактировать …», у кнопок копирования — «Скопировать …», у кнопки ID — «Скопировать ID источника: 4134142 (Timepad)».
- Кнопки правки и копирования прижаты вправо от своего значения.
- **У каждого источника свой набор кнопок** (строка `src-line`): карандаш (правка ссылки) и копирование. Если в ссылке есть числовой ID — добавляется третья кнопка **ID**, которая копирует только число. ID распознаётся у «Элементов» (`elementy.ru/events/<id>`), **ВДНХ** (`vdnh.ru/events/<id>`, правило 30.09.2026), Timepad (`/event/<id>` и `timepad.ru/<id>`) и Архэ (`arche.ru/events/<id>`). Страницы без числового ID (например, «Месяц науки») кнопки ID не показывают.
- Поле `9. Источники` выводится отдельной строкой на каждый источник, а не одной общей ячейкой.
- Под списком источников есть строка **«новый источник»** с кнопкой правки: вписать в неё ссылку и сохранить — источник добавится в конец списка. Чтобы удалить источник, откройте его правку и очистите поле (пустая строка = удалить).
- Правка списка источников синхронизирует формальное поле `9. Источники` в `prototype.json` — руками его править не нужно.
- На опубликованном сайте (GitHub Pages) правка поля работает, и **«Сохранить» тоже работает**: сервера там нет, поэтому значение сохраняется **в браузере** (localStorage) и подставляется на страницу сразу и после перезагрузки. Правка живёт **до следующего обновления сайта с localhost**: в `prototypes.js` вписана метка сборки, ключ хранилища строится по ней, поэтому после пересборки и публикации все такие правки сами собой исчезают (файл прототипа при этом не меняется — код правки можно забрать кнопкой «Скопировать»). У сохранённого поля появляется кнопка **«Вернуть как было»** — она возвращает значение, которое было на сайте. Правки привязаны к ID прототипа: правка одного события не попадает на страницы других. Скрываются на GitHub Pages только действия с прототипом целиком (комментарий, обратная связь, скрытие, удаление) — им нужен локальный сервер.

Куда ведёт страница после действия (важно):
- **Сохранение** комментария, обратной связи, правки поля и **удаление прототипа** — возвращают в список прототипов: задача передана, событие можно закрыть.
- **Удаление** комментария или обратной связи (✕ у выведенного текста) и кнопка **«Скрыть»** — **остаются на странице события** и перезагружают её. Раньше эти действия уводили в список; теперь это исправлено, потому что событие обычно ещё правится.

Комментарии и обратная связь (`_state.json`) хранятся отдельно от `prototype.json`, поэтому переживают:
- пересборку сайта (`build.py`) и кнопку «Обновить данные»;
- архивирование прототипа — при возврате папки из `_archive` комментарий остаётся на месте;
- обрыв записи файла: `_state.json` пишется через временный файл, рядом лежит `_state.json.bak`, а если основной файл вдруг окажется битым, он переименовывается в `_state.json.broken` (ничего не пропадает молча), а комментарии берутся из резервной копии.

Блок «Об авторе»:
- **если автор есть на «Элементах»** — показывается **полноценный блок: фото, имя, описание** (без кнопок правки: копировать нечего, автор уже в базе);
- **if автор новый** — таблица полей 7.1–7.6 (инвертированное имя, стандартное имя, полное имя, описание автора, фото из источника, файл фотографии) с кнопками правки и копирования. Поля 7.5 (фото) и 7.3 (полное имя) — только если известно; поле 7.6 «Файл фотографии» включается ВСЕГДА (даже если фото из источников нет) — см. скилл event-description.

Что решает, какой блок показать: флаг `"on_elementy"` у автора в `prototype.json`.
- `"on_elementy": true` — только если автора **реально нашли на «Элементах»** (тогда полный блок);
- `"on_elementy": false` или нет флага — новый автор, показываем поля 7.1–7.6.

Несколько авторов у одного события:
- в `prototype.json` пишем **список** `"authors": [ {...}, {...} ]`, а не объект `"author"`. Старый ключ `"author"` (один автор) тоже читается — совместимость сохранена;
- у каждого автора свой `"on_elementy"`, свой `photo` и свой `block_html`; блоки «Об авторе» идут по порядку в списке;
- в шапке страницы выводится строка `Автор: …` (один автор) или `Авторы: …` (несколько, через « и »);
- в шапке и в подписи к блокам имя показывается в форме `Имя Фамилия` (как в Elementy), а в тексте описания — в форме `Имя Фамилия` с выделением `<b><i>…</i></b>`;
- ключ правки полей автора — составной `индекс:номер`, например `0:7.1` для первого автора и `1:7.4` для второго (`protolib.parse_author_key`).

Где брать описание и фото автора, если он уже на «Элементах»: с любой страницы события «Элементов» с этим автором — блок «Об авторе» там уже собран. Проверено на событии 449969 (презентация книги «Мозг и его Я», 10.04.2026): оттуда взяты описания и фото Анохина и Черниговской. Фото кладутся в `photo` полным адресом (`https://elementy.ru/images/eltevents/…`).

Сам факт непустого `block_html` **не** означает, что автор есть на «Элементах»: `block_html` — это просто текст описания, он бывает заполнен у любого автора. Раньше решение принималось по нему, и новые авторы ошибочно показывались как «уже в базе», а стандартные поля 7.1–7.4 скрывались.

ГЛАВНОЕ ПРАВИЛО: ничего не выдумывать. В прототипе не должно быть НИ ОДНОГО факта, которого нет на источниках.
- Адрес, аудитория, телефон, метро и время пешком — только если это написано на источнике. Если источник про метро ничего не говорит — строку `<b>Проезд:</b>` не пишем (даже если метро в городе есть).
- Каждый источник в списке должен открываться (проверять HTTP-статус). Если ссылка даёт 404 — источник неверный: взять правильный URL с источника или из текста прототипа, а не оставлять старый.
- Если сомневаетесь, значение ставит **пользователь** — агент не догадывается.

Верхняя панель: переключатель показа, «Лектории», «Обновить данные» и «Пост в Телеграм» стоят в одну строку; надпись «Показывать» убрана, подписи сокращены («всё», ««Элементы»», «прототипы», «скрытые», «Лектории»).

Если кнопка не сработала и появилось сообщение «сервер запущен старой версией» — значит, на компьютере работает старый `serve.py`: закройте его и снова запустите `python serve.py`.

Незакрытые окна (защита от потери текста):
- Кнопка «Закрыть» в окне «Комментарий» и «Обратная связь», если внутри есть непустой текст (пробелы и переводы строк не считаются), спрашивает: «Закрыть без сохранения?» — «Отмена» возвращает к редактированию, «Закрыть без сохранения» выбрасывает правку.
- Пустой комментарий (только пробелы) закрывается сразу, без вопроса.
- **ESC** закрывает окно, если правок не было. Если правки есть, первый ESC ничего не закрывает и показывает подсказку «В окне несохранённые изменения: ESC ещё раз — закрыть без сохранения»; второй ESC закрывает.
- Удаление по иконке «✕» тоже спрашивает подтверждение.
- Окно на сайте одно и то же (переиспользуется), поэтому кнопки в нём работают только для **сейчас открытого** окна: обработчик от предыдущего окна снимается (`wireModal` в `prototypes.js`). Без этого «Сохранить» во втором окне правки переписывал бы ещё и поле из первого.
- После сохранения обратной связи или комментария из окна события происходит возврат **в список** (окно открывалось со страницы прототипа — сохранили и ушли на главную).

Проверка перед показом любого прототипа (правило проекта, выполняется помощником):
1. `python -X utf8 tools\check_proto_json.py data\prototypes\<папка>\prototype.json` — детерминированная проверка САМОГО файла прототипа (nbsp, «ё», тире, инициалы, KLBLOCK, кавычки-лапки, поле 1 «Привязка», римские цифры, буквенные сокращения, сырой пробел U+00A0). Без пути — проверяются все прототипы сразу.
2. Механические nbsp-ошибки исправляет сам валидатор: `python -X utf8 tools\check_prototype.py --json data\prototypes\<папка>\prototype.json --fix` (режим `--fix`, 28.09.2026) — правит nbsp после однобуквенных предлогов, убирает nbsp после двухбуквенных, ставит nbsp у чисел/тире/инициалов, заменяет «пойдёт» на «пойдет», сущности тире — и сразу показывает отчёт по исправленному тексту.
3. Один сквозной проход «корректура + пост-проверка» (объединён 28.09.2026): скилл `proofreading` (письменный аудит всех «ё» и всех nbsp в файл прототипа) + скилл `post-check` (чек-лист из 16 пунктов, п. 0 — тот же валидатор). Остатки после `--fix` (наводки, «ё» по списку yo_words, кавычки, лапки, римские цифры) правятся одним заходом, потом валидатор прогоняется финально — максимум 2 прогона на прототип.
4. Сборка сайта — один раз, после всех правок: `python -X utf8 build.py` (или её сделает кнопка «Обновить данные»/автопересборка `serve.py`).

### Частичная проверка: правим одно поле — проверяем одно поле (`--only`)

Правило пользователя (01.10.2026): правка конкретных полей прототипа не требует ни полной пересборки текста, ни полной проверки — достаточно проверить и пересобрать ТОЛЬКО изменённые поля. Ключ `--only`:

```
python -X utf8 tools\check_proto_json.py data\prototypes\<ID>\prototype.json --only desc
python -X utf8 tools\check_proto_json.py data\prototypes\<ID>\prototype.json --only 3,6,13
python -X utf8 tools\check_proto_json.py data\prototypes\<ID>\prototype.json --only extra --fix
```

- Области: `fields` (`поля`), `title` (`заголовок`), `annot` (`аннотация`), `lecturer` (`лектор`), `desc` (`описание`, `текст`), `extra` (`доп`, `допинформация`), `authors` (`автор`, `авторы`). Несколько — через запятую.
- Номера полей — как в прототипе: `2`, `2.1`, `6.3`, `7.4`. Можно смешивать с областями: `--only desc,7.4`.
- Работает и с `--fix`: автоправки применяются только к выбранным полям, остальные значения файла не трогаются.
- Проверка поля 1 «Привязка» входит в выборку только при `--only fields` или `--only 1`.
- Неизвестное слово в списке — понятная ошибка с перечнем допустимых значений, а не «тихая» проверка не того.
- В выводе печатается пометка «ЧАСТИЧНАЯ ПРОВЕРКА»: она не заменяет полный прогон — **перед показом пользователю прогон всё равно полный**.


Небольшой команды «отладить один пробел» между прогонами валидатора НЕ гоняем
(бережное расходование, 28.09.2026): чиним все ошибки одним заходом.
Старые прототипы (уже загруженные на сайт) валидатором не проверяются и не
переделываются.

Два правила, которые легко забыть (записаны 28.09.2026 по правкам СПбГУ):
- неразбиваемый пробел в файле прототипа пишется **только текстом `&nbsp;`**; сырой символ неразбиваемого пробела в данных запрещён;
- пробелы источника не образец: nbsp ставится и убирается по правилам, проверяется в обе стороны (и лишние, и забытые).

### После `<br>` — всегда пустая строка (правило 01.10.2026)

В «Доп.информации» (`extra_html`) после каждого `<br>` ставим **ровно одну пустую строку**. `<br>` — это перенос строки внутри абзаца, а не разделитель блоков, поэтому без пустой строки исходник слипается: читается, что это одна длинная строка.

```html
<p><b>Адрес:</b> Москва, ул.&nbsp;Восточная, д.&nbsp;4.<br>

<b>Проезд:</b> метро «Автозаводская». <a href="…">Карта</a>.</p>
```

- Правило касается **только** `extra_html`. В формальных полях и в тексте описания не трогаем: там `<br>` может давать настоящий перенос строки или лишний абзац.
- На странице ничего не меняется — пустая строка в HTML не видна, это правило только для читаемости исходника.
- Проверяет валидатор (тег `1f`): `python -X utf8 tools\check_proto_json.py data\prototypes\<ID>\prototype.json --only extra`. Ошибка: «после `<br>` нет ровно одной пустой строки».
- Правится автоматически: та же команда с `--fix` (проверено 01.10.2026 на всех 60 прототипах, 78 блоков — изменились только пробелы, ни одной буквы текста).
- Считать вручную не нужно: и лишние пустые строки, и пробелы в конце строки, и текст сразу после `<br>` — всё приводится к канону, повторный прогон ничего не меняет.

Новые прототипы добавляются копированием папки и правкой `prototype.json`; `build.py` подхватывает их сам.

Автопересборка (от 28.09.2026): запущенный `python serve.py` следит за папкой `data\prototypes` (`prototype.json`, `_state.json`) и, если прототип изменился извне (в редакторе или агентом), сам пересобирает сайт — `site/` обновляется без кнопки «Обновить данные». Между изменениями и пересборкой — маленькая задержка; пока идёт обновление данных или только что была пересборка после действия с прототипом, автопересборка не запускается (чтобы не конфликтовать). В консоли сервера видна строка «Автопересборка после правки прототипа: готово».

## 4в. Пакетный сбор: прототипы Medio Modo

События лектория Medio Modo (mediomodo.ru) собираются из сайта организатора отдельным конвейером напрямую в обычные прототипы `data/prototypes\MM-*`:

```
python -X utf8 tools\mm_parse.py            # скачать страницы → data\raw\mediomodo\*.html + events.json
python -X utf8 tools\author_elementy.py     # искать авторов на «Элементах» → data\raw\authors.json
python -X utf8 tools\mm_title.py            # показать title/og:title/h1 страницы (для сверки названий)
python -X utf8 tools\mm_prototype.py        # собрать прототипы по конфигам из data\raw\mm_proto_data.py
python -X utf8 tools\check_all_mm.py        # прогнать валидатор по всем собранным прототипам разом
```

- Все конфиги — в `data\raw\mm_proto_data.py`: словарь площадок `VENUES` (короткое имя, город, адрес, карта, контакты) и словарь событий `EVENTS` (ключ — слаг, например `gelfand-msk-istoriya-epidemij`).
- Имя прототипа генератор строит сам: `MM-ГГММДД-слаг`. Оно не меняется от запуска к запуску, чтобы не терялись комментарии и скрытие (`_state.json`).
- Названия лекций, тематики, блоки авторов — только из источника или с «Элементов». Если на странице источника названия нет — спрашивать пользователя (пример: `drobyshevskij-piter-dop`, название подтвердил пользователь 24.09.2026).
- Если название лекции на странице лежит в блоке афиши `t1060__descr` (а не в `<title>`/`og:title`/`h1`) — проверять вручную по `mm_title.py` или по кэшу HTML.
- Несколько лекторов фестиваля: у каждого дополнительного лектора своя строка админки `2.b/2.c`, `4.b/4.c`, `7.b/7.c` — «Дата события (лектор N)», «Лекция Имя «Название»» (название из `author_titles`), «Дата и время (лектор N)».
- В `tools\check_prototype.py` заведено исключение к правилу римских цифр: цифра после слова латиницей («GTA VI», «Grand Theft Auto VI») — часть названия, а не римский номер (решение пользователя 29.09.2026).
- Карты, найденные поиском (на странице источника ссылки на карту нет), помечаются в `VENUES` меткой `(ЗАМЕНИТЬ!)` — перед публикацией уточнить у пользователя.
- Онлайн-трансляция: парсер (mm_parse.py) фиксирует по карточке события пункт «Онлайн-трансляция» в полях `online`/`has_online`. Генератор (mm_prototype.py) при наличии трансляции добавляет «и&nbsp;ОНЛАЙН» в аннотацию и в шапку/интро описания; для таких событий цена «от N руб.» — это цена трансляции (отдельную цену не указываем). Проверять список трансляций можно по https://mediomodo.ru/online (страница подгружается скриптом, в кэше списка нет — ориентироваться на `online` в events.json).
- Блок «Как добраться» в `VENUES` (поле `addr_html`) повторяет структуру «Элементов»: «Адрес: <организация>, <адрес>.<br>Проезд: метро «…». <a=Карта>». Для площадок, которых нет на «Элементах», организация и адрес берутся из блока howto источника; строка «Проезд» добавляется, если у площадки есть ближайшая станция метро. Карты, которые нельзя проверить, помечаются `(ЗАМЕНИТЬ!)`.

После любых изменений (правил скрипты, обновил данные, поправил памятку):

```
git add -A
git commit -m "коротко: что изменилось"
git push
```

Перед `git commit` обязательно проверяется, что все навыки (скиллы) в
порядке — это делает скрипт:
```
python -X utf8 tools\check_skills.py
```
Если он написал «РЕЗУЛЬТАТ: все скиллы валидны» — можно коммитить. Если
найдены проблемы — их надо сначала исправить и прогнать проверку заново.
Эта же проверка прогоняется после запуска проекта / открытия новой
сессии — чтобы убедиться, что все скиллы загрузились нормально.

Каждый `git push` автоматически пересобирает сайт на GitHub и публикует его.

git status          # какие файлы изменены, но ещё не записаны

## 6а. Порядок событий на сайте = порядок на «Элементах» (правило 01.10.2026)

Порядок карточек на сайте важен и должен совпадать с «Элементами». Там список упорядочен по дате и времени начала, а при их совпадении решает скрытое поле «привязка» (у нас — формальное поле 1 прототипа). Само значение привязки у событий одной даты-времени одинаковое, поэтому порядок внутри такой группы задан тем, в каком порядке события стоят в афише. Раньше у нас вторичного ключа не было вовсе: порядок держался на стабильности сортировки и на порядке, в каком скрипт сложил события в файл. Теперь он хранится явно.

Ключ сортировки на сайте: **дата → время → `ord`**.

- `ord` — номер события **внутри своей пары «дата + время»**: `1, 2, 3…` в том порядке, в каком события идут в афише «Элементов». Поле хранится в `data\events.json` у каждого события.
- Поле `pos` (сырая позиция карточки в афише) в файл **не пишется** — оно нужно только на время сбора. Иначе новое событие сдвинуло бы чужие номера и в отчёте появлялись бы ложные «изменения».
- Смена `ord` не считается изменением события: сверка изменений смотрит только заголовок, лектора, дату, лекторий, город, площадку и цену.
- Совпадения реальные: в снимке от 01.10.2026 — 9 групп (20 событий), где дата и время совпадают, поэтому вторичный ключ действительно нужен.
- Прототипы на «Элементах» ещё не опубликованы, их настоящего места в группе никто не знает. Детерминированное правило: события «Элементов» идут раньше прототипов, прототипы между собой — по алфавиту ID папки.
- Порядок в календаре, в посте в Телеграм и в навигации «предыдущее/следующее» на страницах событий считается по тому же ключу.

Следить за порядком надо при каждой загрузке данных — это делает `scrape.py`:

- порядок в группе пересчитывается по позициям карточек в афише и записывается в `ord` **до** слияния со старыми данными (поэтому событие получает свежий порядок, даже если описание не менялось);
- если «Элементы» поменяли местами события внутри одной даты-времени, они попадают в отчёт `order_changed` (файл `data\update_report.json`), печатаются в консоль, показываются в панели обновления отдельным блоком «ПОРЯДОК НА «ЭЛЕМЕНТАХ»» и вписываются в подпись коммита;
- после записи файла выполняется проверка: если что-то не сходится, печатается «ОШИБКА ПОРЯДКА (нужна правка)».

Отдельно можно проверить файл данных в любой момент:

```
python -X utf8 tools\check_events_order.py
```

Команда печатает все группы с совпадением даты и времени с их номерами и завершается строкой «порядок верный» либо списком проблем.

### Критерий отбора: научно-популярность по содержанию, а НЕ формат (01.10.2026)

Берём научно-популярные события, а не всё подряд по форме. Это **общая база** для всех площадок, а не готовый ответ: что считать научно-популярным, зависит от площадки и особенно от **гуманитарной темы**.

- Лекция, семинар, экскурсия-лекция, встреча с учёным — **берём**, если по существу научные.
- Формат не решает: **дискуссия, клуб, круглый стол берутся**, если по содержанию научные (например, дискуссия между учёными). Одно только слово «дискуссия» в названии ничего не значит.
- **Гуманитарная область — отдельная головная болька.** История, философия, язык, литература, искусство научно-популярными бывают: лекция «Язык как отражение культурного кода» (Вечерняя школа ЗИЛ, берём) или семинар по поэтике — научные по содержанию.   А разговор о романе сам по себе — уже нет. Здесь «по содержанию» решает, а не
  область по умолчанию, и сомнительные случаи уточняем у пользователя.
- **Лингвистику берём почти всегда** (устройство языка, история языка, социолингвистика, язык и общество, язык и мышление): это наука, а не «разговор о книге». Практически все лингвистические лекции проходят отбор — даже в виде «вечера школы» или клуба. Исключение — когда речь не о науке, а об изучении иностранного языка как практики.
- Однозначно ненаучное (концерты, языковые и разговорные клубы, театральные клубы, тренинги, мастер-классы, практикумы, квесты, прогулки без научной части) **не берём**.
- Спорные случаи (не понятно, научное или нет) — спрашиваем пользователя, не решаем молча.
- Нюансы по конкретной площадке закрепляем в её карточке `reference\lectories.md`, чтобы не переспрашивать по одному и тому же.

### Три правила из разбора ВСмысле (30.09.2026)

1. **Дату события берём из АНОНСА, а не из Timepad.** В лектории «ВСмысле» лекции
   повторяются: один и тот же Timepad может висеть в анонсе и вести на ПРОШЕДШУЮ сессию.
   Пример: «Смена настроения» Алипова — в анонсе **30.10.2026 19:00**, а Timepad 4188236 —
   это 13.09.2026 (уже прошла). Ставим будущую дату из анонса.
   Сверка: заголовок анонса (`ДД.ММ.ГГГГ ЧЧ:ММ`) против всех дат на странице Timepad.
2. **Поле 3 «Полный заголовок с подзаголовком»** = `подзаголовок<br>полный заголовок без
   подзаголовка`. Если подзаголовка (поле 6) нет — поле 3 равно полю 4
   («Лекция Лектора «Название»»), а НЕ только названию лекции.
   Если курс/серию НЕ объявляем (например, «7 чудес света» Бутягина - это уже
   часть названия лекции) - тоже стандартный заголовок: поле 3 = поле 4,
   поле 6 пусто, в шапке без «из курса» (исправлено в `VS-261007`, `VS-261119`).
   Исправлено в `VS-261004` (Саундтрек), `VS-261115` (Мозг), `VS-261020` (Тимс),
   `VS-261025` (Семихатов). У Бутягина (`VS-261007`, `VS-261119`) курс — поле 3 =
   `название<br>Лекция из курса …`.
3. **Формулировки про «узнаете»:** «В лекции вы узнаете» — нельзя. Правильно «На лекции»,
   ещё лучше просто «Вы узнаете…» (без «на лекции»). В списках вида «мы разберём:» —
   либо перечисление абзацами, либо «Вы узнаете:».
4. **Ссылки на билеты без личных и региональных параметров (01.10.2026).** Виджет
   Яндекс Афиши у ВСмысле даёт ссылки вида
   `…ticketsteam-9711@439656?clientKey=acfbfa99-…&regionId=2` — такой «хвост» убираем
   целиком, остаётся `…ticketsteam-9711@439656` (ссылка работает). Убираем также
   метки `utm_*`, `yclid`, `ymclid`, `gclid`, `fbclid`, `_openstat`, `erid`.
   НЕ трогаем рабочие параметры: `?p=157145`, `?page_id=369`, `?agent_id=museum151`,
   `?text=…` (наши ссылки на карты), `?period=m`, `?42`.
   Правило действует для всех организаторов; при сомнении — спросить.
   Подчищены 7 прототипов ВСмысле (в поле 10 и в «Доп.информации»);
   `build.py` дополнительно чистит такие параметры при выводе (`clean_url`),
   так что старые ссылки из `data\events.json` тоже не попадут на сайт.

## 11. Архэ: страница события и ID Timepad (правило 04.10.2026)

### Правильный адрес страницы события

У лекций «Архэ» правильный адрес такой:

```
https://arhe.msk.ru/?post_type=tribe_events&p=<tooltip-id>
```

Что НЕ работает (проверено 04.10.2026 на трёх событиях):

- `?p=<tooltip-id>` — отдаёт 404;
- `?p=<tooltip-id+1>` — обычная запись WordPress (`single-post`), а не
  `single-tribe_events`, то есть не страница события (иногда тоже 404);
  если такой адрес открывается и текст совпадает — это зеркало, источником
  он не считается;
- `?tribe_events=<транслит названия>` — старый дублирующий адрес.

Готовый сборщик: `python -X utf8 tools\scrape_arhe.py` (функция
`resolve_arhe_url`) — он сам перебирает варианты и берёт рабочий.

### Как взять ID события Timepad и понять, какой это аккаунт

В HTML карточки события Timepad есть два нужных атрибута:

- `data-twf2s-event--id="4219640"` → ID события, в прототипе `TP-4219640`;
- `data-timepad-customized="13612"` → код аккаунта:
  - `13612` → `https://arhe-events.timepad.ru/event/<id>/`;
  - `44486` → `https://tsentr-arhe-v-sankt-peter.timepad.ru/event/<id>/`.

Один и тот же анонс может жить в обоих аккаунтах (иногда в разных датах),
поэтому проверяем оба и в поле «Источники» указываем все найденные адреса.
