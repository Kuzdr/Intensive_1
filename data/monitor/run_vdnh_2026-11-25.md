## Стандартные критерии деления на очереди (по проекту)
- **Нужно**: научно-популярное/публичное научное событие (лекция, научный разговор в духе «Элементов»), дата будущая (или актуальная), не дубль уже опубликованного на «Элементах»/в data/events.json и не дубль существующих прототипов; оформление по правилам проекта возможно.
- **Сомнительные**: спорный тип (мастер-класс/экскурсия с научным элементом — решать по смыслу), неполные данные в списке, возможный дубль «под вопросом», нужны уточнения/критерии для конкретной площадки/формата.
- **Не нужно** (записывать в отдельный файл, не выводить объёмно в чат): прошедшие даты, явные не-научпоп/не подходящие по стандартам, точные дубли уже учтённых событий. В примечаниях к ВДНХ указано: «не везде лекции; фильтровать по смыслу/названию».

## Текущее состояние в репозитории (снимок)
- В data/events.json: найдено ~15 записей с площадкой, содержащей «ВДНХ» (организатор/source в части записей могут быть неполными — при сверке проверять по дате+названию+площадке).
- Прототипы с упоминанием «ВДНХ»/vdnh в тексте (по поиску по файлам): TP-4306298, TP-4312127, TP-4314509, TP-4316212, TP-4317015, TP-4318063, TP-4318314 (при детальном обзоре проверить полный список).

## Ограничения текущей среды
- Списки vdnh.ru могут быть JS-тяжёлыми; Timepad — только Edge+CDP. Полный автоматический сбор списков прямо сейчас без интерактивного CDP/ручного сохранения кэшей сделать нельзя.
- Для «Элементов» сверка лучше после python -X utf8 scrape.py → python -X utf8 build.py (с учётом правил доступности).

## Рекомендуемые шаги
1. Обновить сверку с «Элементами» при возможности (scrape.py → uild.py).
2. Собрать списки по 5 источникам ВДНХ (вручную/через CDP и кэши), нормализовать ID/URL.
3. Для каждого источника сравнить с data/monitor/known_by_source.json (завести ключи, например: dnh_lektorij, dnh_kosmos, dnh_slovo, dnh_atom_lab_timepad, dnh_muzey_biotech_timepad) — известные не грузить повторно.
4. Новые кандидаты сверить с другими источниками этого обзора, с data/events.json (ВДНХ), с прототипами; распределить по Нужно/Сомнительные/Не нужно.
5. «Не нужно» — в отдельный файл в data/monitor/ (не в чат); «Нужно/Сомнительные» — в data/monitor/pending.json или на утверждение пользователю; после утверждения — прототипы по event-description.
