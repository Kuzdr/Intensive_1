# Шаблон прототипа события

Каркас `prototype.json` для нового прототипа. Папка названа с `_` впереди
намеренно: `build.py`, `protolib.list_ids()`, `serve.py` и оба валидатора
(`tools/check_proto_json.py`, `tools/check_prototype.py`) пропускают папки,
которые начинаются с `_` или `.`, — поэтому этот шаблон не попадёт ни на сайт,
ни в проверки. Так же устроена папка `_archive`.

## Как пользоваться

1. Скопировать папку `_template` в `data/prototypes/<ID>` (например,
   `data/prototypes/TP-4194633`). ID — это имя папки и поле 0.
2. Заполнить `prototype.json`, заменяя всё в угловых скобках `<…>`.
3. Проверить перед показом пользователю:

       python -X utf8 tools\check_proto_json.py data\prototypes\<ID>\prototype.json

   Точечная правка отдельных полей (без полного прогона):

       python -X utf8 tools\check_proto_json.py data\prototypes\<ID>\prototype.json --only desc
       python -X utf8 tools\check_proto_json.py data\prototypes\<ID>\prototype.json --only 3,6,13 --fix

   Допустимые области `--only`: `fields` (поля), `title`, `annot`, `lecturer`,
   `desc`, `extra`, `authors`, `notes` — либо номера полей (`3`, `6.3`, `7.4`).

4. Пересобрать сайт: `python -X utf8 build.py`.

## Верхний уровень `prototype.json`

Обязательные ключи:

| Ключ | Что это |
|------|---------|
| `id` | ID события = имя папки |
| `lectory` | лекторий (поле 6.3) |
| `date_iso` | дата события `ГГГГ-ММ-ДД` |
| `time_start`, `time_end` | время начала/окончания `ЧЧ:ММ` (окончание можно оставлять пустым, если неизвестно) |
| `city` | город |
| `place` | площадка (= поле 6.2, значение из `reference/lists/place.md`) |
| `lecturer` | автор, «Имя Фамилия» (пусто, если автор не установлен) |
| `title` | название лекции (HTML, с `&nbsp;`) |
| `types` | типы, напр. `["Лекция"]` |
| `topics` | тематики, напр. `["Зоология"]` |
| `price_short` | краткая цена для карточки |
| `annot` | аннотация карточки на главной |
| `url` | основной источник / ссылка регистрации |
| `sources` | список URL источников |
| `fields` | формальные поля 0–14 (см. ниже) |
| `desc_html` | HTML описания: шапка + `<KLBLOCK eltclub_authors_about/>` + `<blockquote>` |
| `extra_html` | массив абзацев «Дополнительной информации» |
| `authors` | массив авторов (см. `author.md`) |
| `notes` | техзаметки (видны на странице прототипа) |

Необязательные ключи (в шаблоне оставлены пустыми — включаем по надобности):

| Ключ | Когда нужен |
|------|-------------|
| `verbatim_fragments` | массив дословных вставок с «Элементов» (валидатор пропускает в них проверки nbsp/«ё»/тире) |
| `reg_labels` | подписи к нескольким ссылкам поля 10 по порядку, напр. `["билет на лекцию", "билет на онлайн-трансляцию"]` (только показ на странице прототипа) |
| `photo_file` | имя файла фото автора для загрузки (если ведётся отдельно от авторов) |

## Формальные поля (`fields`)

Порядок и названия — из `protolib.FIELD_ORDER`:

```
0   ID события
1   Привязка (ГГГГ.ММ.ДД + индекс времени; считается в check_protojson)
2   Дата события: дата, город, площадка [, и ОНЛАЙН], время
2.1 Начало события: «ДД месяц ГГГГ» (без nbsp после числа)
2.2 Время начала
2.3 Поставить: текущая дата «ДД месяц ГГГГ»
2.4 Снять: следующий день после события «ДД месяц ГГГГ»
3   Полный заголовок с подзаголовком: подзаголовок<br>тип автор «название»
4   Полный заголовок без подзаголовка: тип автор «название»
5   Название лекции (без кавычек)
6   Подзаголовок (лекторий/организатор/цикл)
6.1 Тип
6.2 Место (из reference/lists/place.md)
6.3 Лекторий (из reference/lists/lectorium.md)
6.4 Тематики (из reference/lists/theme.md)
7   Дата и время
8   Место (город, площадка [, и ОНЛАЙН])
9   Источники (URL, каждый на новой строке)
10  URL регистрации/покупки билета (у Timepad — с #register; иначе пусто)
11  Стоимость
12  Возрастные ограничения (пусто, если не указаны)
13  Адрес
14  Аудитория (по умолчанию «Для всех»)
```

Частичные поля событий-фестивалей (когда на одной странице несколько лекторов
или сеансов) добавляются В ДОПОЛНЕНИЕ к основным и повторяют их по образцу:

- лектор 2: `2.b`, `4.b`, `7.b`
- лектор 3: `2.c`, `4.c`, `7.c`

`name` у них, как в реальных прототипах, — «Дата события (лектор 2)»,
«Полный заголовок без подзаголовка (лектор 2)», «Дата и время (лектор 2)» и т.д.

## Онлайн / офлайн

- Только офлайн: в полях 2 и 8 просто «Город, Площадка».
- Есть онлайн И офлайн: добавить «и&nbsp;ОНЛАЙН» в поля 2 и 8 и в первый абзац
  шапки (`desc_html`).
- Только онлайн: в полях 2 и 8 — «ОНЛАЙН», площадки и адреса нет.

## Авторы — 3 варианта

Скелет с готовыми блоками: `author.md`. Кратко:

1. **Автор уже на «Элементах»** (`on_elementy: true`): поля `7.1`, `7.2`,
   `7.3` (если известно отчество), `7.4`, `7.5` (фото с «Элементов»).
   Поле `7.6` НЕ заполняем.
2. **Новый автор, фото есть в источнике** (`on_elementy: false`): `7.1`,
   `7.2`, `7.3` (если есть), `7.4`, `7.5` (URL фото из источника), `7.6`
   (`familiya-imya_120.jpg`).
3. **Новый автор, фото нигде нет** (`on_elementy: false`): `7.1`, `7.2`,
   `7.3` (если есть), `7.4`, `7.6`. Поле `7.5` отсутствует, о причине —
   в `notes`.

`7.4` дублируется в `block_html` (HTML-форма) и в поле `7.4` — оба должны
совпадать. Поле `7.3` убирается целиком, если отчество неизвестно.

Проверка «есть ли автор на „Элементах“» — только поиском по сайту:
`https://elementy.ru/find?objs=eltevents&words=Фамилия` (локальный
`data/events.json` доказательством отсутствия автора НЕ является).

## Лектории и площадки

- Карточки лекториев живут в `reference/lectories.md`. Готовый скелет
  карточки — `lectorium.md` в этой папке.
- Площадки — строки в `reference/lists/place.md` формата `ID : значение`.
  Готовый скелет строки — `place.md`.
