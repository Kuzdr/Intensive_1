# Регулярные обходы лекториев

## Важное правило (с 22.11.2026)

- **JSON вручную не редактируем.**
  Правки и дополнения в `lectories.json` и `known_events.json` вносит ИИ:
  напишите поправку в чат, и он изменит файлы.
- **Прошедшие события не показываем и не добавляем в реестр никогда.**
  Обход сам отбрасывает события с датой раньше сегодняшней; старые записи
  удалены из реестра 22.11.2026.
- **Каждый отчёт об обходе обязан содержать ПОЛНЫЙ список кандидатов
  со ссылками** — не только счётчики и ID. Для каждого события из реестра
  со статусом `candidate` показываем: ключ, дату/время, **автора**, заголовок
  и URL. Заведомо неподходящие не показываем вовсе; подходящие и сомнительные
  выводим отдельными группами (поле `review`: `include`, `doubt`, `hide`).
  Правило действует всегда, даже если кандидатов много.
- **Сверка с прототипами — одинаковая для всех лекториев.** Если URL события
  совпадает с `url`/`sources` любого прототипа в `data/prototypes/`, событие
  в кандидаты не попадает ни у сборщика, ни без него; оно печатается отдельной
  строкой «уже есть прототип — не кандидаты». Проверка одна (`split_prototyped`),
  повод: 22.11.2026 лекция Соколовой (TP-4297595) попала в выдачу, хотя прототип
  с тем же URL давно был готов, — старая проверка была только у «Прямой речи».
- **Одно событие из двух источников — одна запись в реестре.** Отпечаток —
  дата + нормализованный заголовок (`ё`→`е`, регистр/кавычки не важны,
  приставки «Лекция…» и «Вечерняя школа ЗИЛ» убираются); нет заголовка —
  дата + автор. `same_event()` / `find_existing()`: найденное событие с уже
  известным отпечатком не печатается как новое, а при `--bootstrap` не создаёт
  вторую запись — URL дописывается в `also_urls` существующей. Повод:
  22.11.2026 лекцию Сердотецкого нашли в Timepad ЗИЛ и на сайте `zilcc.ru`
  и подали как два разных события. Проверить уже заведённые пары: `--check-dups`.
- **BOM и защита реестра.** `load_json()` читает `utf-8-sig`; если реестр не
  читается, CLI выходит без изменений (22.11.2026 пустой fallback стёр 124
  события, оставив 7).

## 1. `lectories.json` — список лекториев и источников

Каждый лекторий — отдельный объект:

- `key` — короткий латинский идентификатор (`pryamaya`, `arhe`, …);
- `name` — название, как показывать в отчёте;
- `enabled` — `true`, если лекторий нужно проверять при обходе;
- `collector` — имя сборщика: `pryamaya`, `arhe` или пустая строка;
- `sources` — массив источников (`kind`, `url`, `note`);
- `criteria` — напоминание, что берём, а что нет;
- `reference` — путь к подробной карточке лектория в навыке.

Если `collector` пуст, при обходе лекторий не опрашивается, но **кандидаты
из реестра всё равно печатаются** со всеми ссылками и авторами — правило
полного списка кандидатов действует и здесь. Надпись «сборщик не назначен»
появляется только если в реестре кандидатов нет (это не ошибка).
Сейчас все лектории включены (`enabled: true`), в том числе новые источники
без сборщика.

Все источники лектория перечисляются в `sources`; при каждой проверке
обновлений просматриваются **все** его источники. Так, для ВДНХ — сайт
`vdnh.ru/events/` и пять Timepad-лент, для «Архэ» — календарь, четыре раздела
сайта и оба Timepad-аккаунта, для ЗИЛ — Timepad и сайт `zilcc.ru`.
22.11.2026 добавлены `planetalib` (Библиотека Планетарий 1: Timepad
`planetalib.timepad.ru/events/` и сайт `planetarium.one`) и `oxta8`
(Библиотека им. В. В. Маяковского Охта-8: Timepad `oxta8.timepad.ru/events/`
и полная афиша «Элементов» для сверки дублей); у обоих `collector` пустой,
ID — `TP-<id Timepad>`. Timepad у этих лекториев отдаёт капчу, поэтому ленты
и карточки читаются через обычный Edge/CDP (`tp_cdp.py`, порт 9223).
Лекция Михайлова 29.11 (TP-4239652) — точный дубль «Элементов» 450840,
помечена `duplicate` и не добавлялась, хотя пользователь просил «все три».

## 2. `known_events.json` — реестр известных событий

События сгруппированы по `key` лектория. У каждого события:

- `key` — устойчивый идентификатор (`PR-<id лекции>` у «Прямой речи»,
  `TP-<id Timepad>` у «Архэ»); смена заголовка не меняет ключ;
- `date`, `time`, `title`, `subtitle`, `author`, `url` — что нашли;
- `review` — у любого кандидата: `include` (явно вносить), `doubt` (сомнительно),
  `hide` (не показывать совсем); у кандидатов без `review` группа
  «КАНДИДАТЫ». Поле заменено с «только Прямая речь» 22.11.2026.
- `status` — один из:
  - `candidate` — найдено, решение ещё не принято;
  - `added` — добавлено в прототип/на сайт;
  - `on_elementy` — уже опубликовано на «Элементах»;
  - `rejected` — отвергнуто (причина в `note`);
  - `duplicate` — дубль опубликованного (ID в `note`);
- `note`, `first_seen`, `last_seen`, `updated` — служебные поля.

Решение пользователя 22.11.2026 по второму проходу: ВСмысле и Medio Modo —
все, ЗИЛ — только Губанова, Сердотецкий в `doubt`, Соколова уже оформлена
прототипом TP-4297595, Герцен — Железнов; ВДНХ и Некрасовка — `hide`.

## Дубль = дата + автор/заголовок (правило 22.11.2026)

Совпадение **только даты** дублем не считается: в один день на «Элементах»
бывает по десять лекций. Совпадение **только похожего заголовка** тоже не
считается, если дата другая (например, «Ресурсы космоса» Сурдина 21.03.2026
и 21.03.2027 — разные события). Дубль — это событие с той же датой **и** тем же
автором/заголовком, что уже опубликовано на «Элементах».

Перед тем как добавить кандидата в реестр:

1. выгрузить полную афишу `https://elementy.ru/events` **без параметров** —
   там все предстоящие события. Локальный `data/events.json` — только снимок
   ближайших ~95 событий (сейчас до 29.12.2026), одного его мало;
2. сверить дату + автора/заголовок с афишей. Для дат вне снимка (январь–март
   2027) дополнительно искать по фамилии:
   `https://elementy.ru/find?objs=eltevents&words=<Фамилия>`;
3. найденное совпадение отметить `status: duplicate`, в `note` записать
   `ДУБЛЬ: уже на «Элементах» (ID 450765)` — после этого кандидат не выводится.

Так, 22.11.2026 по полной афише помечено 35 дублей; после этого в выдаче
осталось 26 будущих кандидатов. У лекции Корнейчика 14.01.2027 поиск
«Элементов» показывает 2027 год, а шапка страницы 450765 — 2026: расхождение
на стороне «Элементов», дублем всё равно считаем.

## Команды

```bat
python -X utf8 tools\sweep_lectories.py --list
python -X utf8 tools\sweep_lectories.py
python -X utf8 tools\sweep_lectories.py --lectory pryamaya
python -X utf8 tools\sweep_lectories.py --refresh
python -X utf8 tools\sweep_lectories.py --check-dups
python -X utf8 tools\sweep_lectories.py --bootstrap
python -X utf8 tools\sweep_lectories.py --mark PR-8935 --mark-status added --note "прототип создан"
python -X utf8 tools\sweep_lectories.py --mark PR-8935 --mark-status rejected --note "игра, не лекция"
python -X utf8 tools\sweep_lectories.py --json report.json
```

- Обычный запуск печатает **НОВОЕ** (чего нет в реестре), сводку по
  известным статусам и полный список ждущих решения кандидатов (с автором
  и ссылкой). Прошедшие события отбрасываются автоматически. Сам реестр
  запуск не меняет.
- `--bootstrap` один раз добавляет все найденные события в реестр со статусом
  из источника. Повторный запуск ничего не дублирует.
- `--mark` меняет статус одной записи (или создаёт её, если ключа ещё нет).
- `--refresh` обновляет кэш «Архэ» (`data/raw/arhe_calendar.json`).
- Если источник недоступен, обход пишет причину в
  `.opencode/skills/event-description/reference/availability_log.md` и
  продолжает остальные лектории; реестр не портится.
